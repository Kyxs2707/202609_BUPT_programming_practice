# MYB 项目实施步骤

> 给后续执行本计划的 Agent：按任务逐项推进并用复选框记录状态；执行时使用 `superpowers:executing-plans`，如用户选择子代理执行方式则使用 `superpowers:subagent-driven-development`。先完成语言和架构设计，再实现依赖这些设计的模块。

**目标：**完成 MYB 通用脚本语言、解释器、自动黑盒测试、Python 性能对比、开发指南以及 Agent 辅助开发的完整应用。

**架构：**本文以 C++17 + Flex + Bison + AST 执行为规划基线。Flex 生成词法分析器，Bison 生成语法分析器；通过自定义语义动作构造 AST，再由自行实现的语义检查和运行时执行。宿主实现语言仍待步骤 1–3 确定；整体核心语法已按 D62 确认，源码与字面量已按 D63 确认，表达式规则已按 D64 确认，基础内置接口已按 D65 确认，整文件文本读写 A 与保留流式扩展 B 已按 D66 确认；四个文本辅助函数已按 D67 确认，程序执行与错误基础规则已按 D68 确认，数据访问检查时机与独立代码块已按 D69 确认，循环变量作用域和三项文法边界已按 D70/D71 确认；文法与 D72 精确显示已写入 v0.2 集中审阅稿，用户已于 2026-10-19 整体确认该语言规范；运行接口细节与候选技术路线留待其后，终端游戏库候选延后单独讨论。

**技术栈：**C++17、Flex、Bison、CMake；Python 用于外部测试驱动和性能测量；测试程序及应用使用 MYB。

**需求依据：**[原始需求文档](../../原始需求文档.md)。本文吸收了此前参考调研和后续 Flex/Bison 讨论，作为接下来的统一工作清单。创建日期：2026-10-11。

**设计讨论进度：**已确认的语言决定、待定项和下一次讨论位置见 [MYB 语言设计讨论记录](../../MYB语言设计讨论记录.md)。执行后续任务时，应先阅读该记录；本计划中的候选语义不等于已经定稿。

全局约束：测试程序使用 MYB；外部驱动可以使用 Python；应用逻辑必须由 MYB 承担。原始需求没有要求 GUI、JIT、并发、继承或性能超过 Python，这些不作为首版交付的前置条件。

## 二、执行顺序与贯穿性工作

**主线：需求范围 → 语言设计 → 解释器设计 → 最小执行链 → 完整前端 → 基础运行时 → 控制流与函数 → 复合类型及 I/O → 测试收口 → 指南 → Agent 应用 → 性能报告 → 交付验收。**

从步骤 4 开始，每增加一项可观察功能，就先写对应 MYB 用例和预期，验证当前实现尚不满足，再实现并运行回归。步骤 9 用于查漏补缺，不是第一次开始测试。

每完成一个可验收的小任务，就更新规范或指南，记录测试结果，并提交相关文件。不要等项目结束后才补造 Git 历史或 Agent 开发过程。

重点审查的五类情况已经分配到后面的任务：

| 容易遗漏的情况 | 预期行为 | 所属步骤 |
|---|---|---|
| 中文字符串、CRLF 换行、路径含空格、输入 EOF | 编码和定位规则一致，命令行可用，EOF 行为可预测 | 4、5、8 |
| 最小负整数、溢出、负数除法、除零 | 按 MYB 规则求值或报错，避免 C++ 未定义行为 | 2、6 |
| 数组/记录共享、循环引用、连续创建对象 | 更新和生命周期符合规范，不悬空，不无界隐性泄漏 | 3、8 |
| 循环中 return、函数递归、异常后的环境恢复 | 控制流和调用栈正确，资源可释放 | 7 |
| 测试脚本死循环、输出错误、非零退出 | 驱动能超时终止、判失败并继续其他用例 | 4、9 |
