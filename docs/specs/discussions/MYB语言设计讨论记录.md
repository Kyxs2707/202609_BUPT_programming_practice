## 2. 已明确的任务理解

老师要求设计一门小型、通用、解释执行的编程语言 MYB，并实现其解释器。“脚本语言”属于编程语言，可以用来编写完整应用；最终应用可以是命令行工具或小游戏，不要求达到 C++/Java 的语言规模或标准库规模。

以下是不同的设计维度，不应混为一谈：

| 维度 | 本项目状态 |
|---|---|
| 通用语言 / 领域专用语言 | 作业要求通用语言 |
| 解释执行 / 编译执行 | 作业要求实现解释器 |
| 静态类型 / 动态类型 | 动态类型；变量可以重新绑定不同类型的值，运算按当前值在运行时检查 |
| 是否隐式转换类型 | 用户选择数字与字符串显式转换，同时允许整数向浮点数提升 |
| 是否使用前端生成器 | C++17 + Flex + Bison + AST 是当前规划候选，尚未正式定稿 |

最初讨论中的 A/B/C 分别是“实用清晰”“强调类型检查”“强调表达特色”三个设计取向，它们不是互斥的语言类别。用户后来明确选择的是动态类型，不能据此认定用户批准了此前所有 A 方案建议。

### 2.1 2026-10-14 范围核查：脚本语言定位与讨论粒度

用户在确认首版循环方案 A 后询问：讨论是否已经出现偏差，MYB 是否越来越像编程语言而不是脚本语言。该问题不是撤销动态类型、结构字段检查或其他已确认决定。

对照原始需求，目标明确是“解释型的通用脚本语言”，并强制包含数组、结构、分支循环、函数，还要求至少 200 行的完整应用。脚本语言属于编程语言；上述能力服务于课程要求，不能仅因提供结构或讨论作用域就判定目标偏离。脚本也不必限于组合命令的 Shell 用途。

助手的范围判断：已确认核心仍能构成小型脚本语言，结构字段类型与可空约束是用户为保护数据而选择的额外设计成本，并不引入全局静态类型检查。真正需要调整的是讨论节奏与粒度：连续逐项比较语言边界，容易让“可以形成清楚规范”的目标扩张成“逐项探索各种语言所有选择”。语义细则仍须在规范和测试中明确，但不必都作为单独的长期取舍议题。

后续流程建议（尚不是新增范围决定）：以源文件直接运行、短程序易写、数据处理与终端应用可表达为检查标准；保留已有决定，集中列出未决项，为相关主题一次给出连贯的推荐规则，用少量完整 MYB 示例验证设计。新增能力先说明具体应用收益和实现成本，扩展方向不自动加入首版。类、继承、泛型、完整静态类型分析等不能因比较其他语言而自动纳入。

## 3. 已确认的语言决定

| 编号 | 决定 | 确认依据与含义 |
|---|---|---|
| D01 | 采用动态类型 | 用户最初选择动态类型，并在整体取向讨论后再次明确采用动态类型、允许重新绑定不同类型。执行时根据实际值检查运算类型；不要求完整静态类型检查器 |
| D02 | 数字与字符串之间要求显式转换 | 用户对“显式转换 / 自动转换”的选择为“使用A”；最初以整数与字符串为例。`1 + "2"` 报类型错误，不能自动变成 `3` 或 `"12"`；加入浮点数后沿用这一设计方向，具体转换接口见 D65 |
| D03 | 首版支持浮点数 | 用户：“首版再加上支持浮点数吧” |
| D04 | 整数可以自动提升为浮点数 | 用户：“整数可以自动提升为浮点数吧”。整数与浮点数混合算术运算时允许提升，例如 `1 + 2.5` 得到浮点结果 `3.5` |
| D05 | 浮点字面量支持科学计数法 | 用户明确要求科学计数法格式。它是一种书写方式，不是新的数值类型，也不表示任意精度 |
| D06 | `/` 始终进行浮点除法 | 用户选择方案 A。即使两个操作数都是整数，结果仍为浮点数，例如 `5 / 2` 为 `2.5`，`4 / 2` 为 `2.0` |
| D07 | 整数除法向下取整，余数与其配套 | 用户于 2026-10-12 修订：“将除法改为向下取整，并修改相关内容，让语言更符合数学习惯”。整数商为数学商的向下取整值，非零余数与除数同号，满足被除数 = 商 × 除数 + 余数；此决定替代此前的整数商与余数规则，不改变 D06 的浮点除法 |
| D08 | 使用固定范围的 Int64 + Float64 | 用户：“使用A固定范围”。首版不实现任意精度整数；整数溢出报错 |
| D09 | 数值异常明确报错 | 用户：“那就明确报错吧”。除零、Int64 溢出、浮点运算产生无穷大或 NaN，均报告错误；普通浮点舍入误差仍允许 |
| D10 | 字符串使用 UTF-8 存储，长度和索引按 Unicode 码点处理 | 用户：“那就按照你的建议吧，正好也可以处理特殊符号”。支持中文和 Unicode 特殊符号；首版不按字素簇计算长度或索引 |
| D11 | 采用不可变字符串 | 用户最初选择 A，并在讨论 C++ 使用习惯与 Unicode 后再次确认：“那就依旧使用不可变字符串吧”。字符串创建后内容不可原地修改；替换、拼接等改变内容的操作通过产生新字符串实现，具体接口仍待定义 |
| D12 | 字符串从 0 开始索引，同时支持负下标，单个索引越界报错 | 用户最新修订：“那就改成支持负下表并使用切片语法吧”。负下标从末尾计数，`-1` 表示最后一个码点；长度为 n 时，有效整数下标范围为 `-n <= i < n`。此决定替代此前仅支持非负下标的决定 |
| D13 | 字符串采用切片语法 | 与 D12 一并确认，采用类似 `s[start:end]` 的形式，按码点截取并返回字符串；左闭右开见 D25，普通端点规则见 D26，首版不支持步长见 D27 |
| D14 | 使用花括号表示代码块 | 用户：“花括号”。条件分支、循环、函数体等代码块使用 `{ ... }` 划定边界，缩进用于可读性、不决定代码块范围；具体写法已按 D62 确认 |
| D15 | 简单语句以分号结束 | 用户：“那就使用分号吧”。赋值、函数调用、返回等简单语句须以 `;` 结束，换行不替代分号 |
| D16 | 变量必须显式声明 | 用户：“需要显式声明”。先声明变量，再对已有变量赋值；给未声明的名称赋值时报错，不自动创建变量。不要求类型标注，声明关键字为 let（D62） |
| D17 | 允许已声明变量重新绑定不同类型的值 | 用户最新修订：“那就改成动态类型，允许重新绑定不同类型吧”。变量不固定为首次初始化值的类型；普通赋值采用右侧值及其类型，替代此前固定变量类型的选择 |
| D18（已废止） | 原固定类型变量的数值赋值转换规则不再适用 | 依赖“变量类型固定”的旧规则被 D17 的最新修订废止。普通赋值不因变量原来的值而转换右侧数值；混合算术中的整数提升仍按 D04，显式浮点转整数仍按 D19 |
| D19 | 浮点数显式转整数时向零截断，超范围报错 | 用户：“那就使用向0截断吧，超出时报错”。去掉小数部分，截断结果须在 Int64 范围内；否则报转换范围错误，不回绕、不钳制到边界。该规则不改变 D07 的整数除法向下取整 |
| D20 | 允许先声明、后初始化，初始化前读取报错 | 用户选择 B：声明时可以没有初始值，初始化前读取在运行时报错。首次赋值建立值绑定，之后可以按修订后的 D17 重新绑定不同类型 |
| D21 | 采用块级作用域 | 用户在局部变量作用域方案中选择：“使用A吧”。代码块内声明的局部变量仅在该块及其内部可见，块外不能通过该局部名称访问；不会因处于同一函数而自动在块外可见 |
| D22 | 首版提供可增长数组 | 用户：“那就提供可增长数组吧”。允许通过增删元素改变数组长度；元素类型另见 D23，具体接口、索引与切片、复制与共享规则仍待设计 |
| D23 | 数组允许混合类型元素 | 用户：“那就使用A允许混合类型吧”。同一数组可以同时容纳不同类型的值，各元素保留自身类型；不按第一个元素锁定整组元素类型，使用元素参与运算时检查实际类型 |
| D24 | 数组单个索引与字符串一致 | 用户在数组下标方案中确认：“与字符串一致”。从 0 开始，支持负下标，单个索引越界报错；越界赋值也报错，不自动扩展长度。此处确认的是索引规则，不是字符串不可变性或尚未确定的切片细则 |
| D25 | 字符串与数组统一采用左闭右开的切片 | 用户对统一切片方案确认：“可以”。`value[start:end]` 包含起点、不包含终点；字符串按码点、数组按元素截取。普通端点规则见 D26，首版不支持步长见 D27，数组切片浅拷贝见 D28 |
| D26 | 普通切片允许省略端点、负端点，越界时截取有效范围 | 用户：“使用A，继续讨论”。起点默认 0，终点默认长度 n；负端点先加 n，再将端点限制在 `[0, n]`；处理后起点不小于终点返回空序列。字符串与数组一致，单个索引越界仍报错 |
| D27 | 首版只支持普通切片 | 用户：“首版只支持普通切片”。仅支持 `value[start:end]` 及端点省略形式，不支持 `value[start:end:step]`，包括显式步长 1；不提供反向切片。负端点仍按 D26 有效，不代表反向遍历 |
| D28 | 数组切片创建新数组，采用浅拷贝 | 用户：“A使用浅拷贝吧”。结果的外层元素槽位和长度独立，内部对象不递归复制；替换结果元素或增删结果元素不改变原数组，修改共享的内部可变对象可能被两边观察到。普通赋值见 D29，参数绑定见 D31 |
| D29 | 普通数组赋值共享对象 | 用户对普通赋值方案确认：“使用A吧”。`b = a` 让 b 绑定 a 当前绑定的同一个数组，不自动复制；修改该数组可从两边观察到。重新给 b 赋另一个值只改变 b 的绑定，不改变 a；`b = a[:]` 则按 D28 获得浅拷贝 |
| D30 | 深拷贝通过宿主内置函数显式请求 | 用户提出由特定函数执行深拷贝，并在澄清实现方式后确认 A：宿主实现，MYB 调用。程序员明确需要并承担复制开销时自行调用，普通赋值和切片不隐式深拷贝；名称、支持类型、共享关系与循环引用已另行确认，见 D59 |
| D31 | 函数参数采用独立局部绑定，数组实参共享对象 | 用户：“那么就使用这个函数传参方式吧”。形参绑定实参表达式求得的值，不隐式复制数组；修改共享数组内容可被调用方观察到，重新赋值形参只改变局部绑定。不是 C++ 的 `T&` 变量别名语义，也不执行隐式深拷贝 |
| D32 | 采用命名结构，字段集合固定 | 用户在澄清结构类型与实例概念后选择 A。先声明结构名称和字段名集合，再创建实例；实例不能动态新增或删除字段。字段值规则另见 D33，不自动引入完整的类机制 |
| D33（已修订） | 结构字段显式声明类型，创建及写入时在运行时检查 | 用户在确认“结构字段声明类型，并在写入时检查”的含义后选择：“那就使用这套方案吧”。替代此前字段可改存任意类型的决定。字段值仍可修改，但须满足声明约束；不合格写入报错，目标字段保留原值。普通变量动态改绑、混合类型数组不变 |
| D34 | 结构实例普通赋值与传参共享对象 | 用户：“那就使用A吧”。沿用数组共享模型，不自动复制实例；修改字段可通过其他绑定观察到，重新绑定变量或形参仅影响该绑定。所有字段写入仍按 D33 检查；独立备份须显式请求复制 |
| D35 | 数值字段允许整数提升，浮点转整数须显式转换 | 用户：“使用A吧”。创建实例及字段写入时，Float64 字段接受 Int64 并转换为 Float64；Int64 字段拒绝浮点值，包括 2.0，须先按 D19 显式转换。字符串不自动转为数值。大整数提升可能损失精度；普通变量赋值不受此字段规则影响 |
| D36 | 首版按字段名称构造实例，保留后续扩展能力 | 用户：“首版先使用A吧，但这个语言要有拓展能力”。显式指定字段名和值，首版不提供按位置构造；构造标点已按 D62 确认。构造完整性与首版不支持默认值见 D37；扩展要求不等于已批准未来默认值、构造函数、方法或继承 |
| D37 | 首版结构构造须填全字段，不提供默认值 | 用户：“首版使用A”。声明的所有字段必须各填写一次，漏填、重复或未知字段均报错；不自动填零或空值。此规则不改变普通变量允许延迟初始化的 D20，后续可另行设计默认值扩展 |
| D38 | 结构字段允许数组及其他结构实例 | 用户：“那就使用A吧”。Array 字段只检查值是数组，元素仍允许混合类型；命名结构字段只接受声明的结构类型实例。初始化或写入已有数组/结构实例共享对象，不自动复制；不据此引入带元素类型约束的数组、可空字段或递归类型声明 |
| D39 | 独立 Bool 类型，条件只接受 Bool | 用户：“使用A”。提供 true/false，合法比较表达式产生 Bool；if/while 条件在运行时检查，非 Bool 值报类型错误，不按数值零/非零或容器空/非空隐式转换。逻辑运算见 D40；int/float 拒绝 Bool（D65），额外 Bool 专用转换接口未确认 |
| D40 | 逻辑运算严格接受并返回 Bool，与/或短路求值 | 用户：“采用这一套”。与/或先求左侧并检查 Bool；左侧为 false 的与、左侧为 true 的或直接返回对应 Bool，跳过右侧；需要求右侧时也检查 Bool。非对 Bool 取反。跳过的表达式不执行且不做运行时类型检查，但仍须语法合法；符号已按 D62 确认为 &&、\|\|、!，完整优先级见 D64 |

### 3.1 类型与转换

动态类型不意味着无类型、不检查错误或任意隐式转换。MYB 中的值仍有类型，运算须检查实际操作数。

当前示例：

```text
1 + "2"          → 类型错误
1 + 2.5          → 3.5，浮点结果
1 + int("2")     → 3，int 名称及严格转换已按 D65 确认
str(1) + "2"     → "12"，字符串 + 拼接已确认，str 转换已按 D65 确认
```

`int`、`float`、`str` 名称与基础转换规则已按 D65 确认；两个字符串使用 + 拼接已确认（D57）。已声明变量可以重新绑定不同类型的值（D17），普通赋值不根据旧值类型进行转换（旧 D18 已废止）。混合算术中的整数提升仍遵循 D04；需要显式将浮点值转成整数时，按 D19 向零截断并检查 Int64 范围。允许重新绑定不意味着运算时允许任意类型混合。

### 3.2 数值类型

- **Int64**：有符号 64 位整数，范围为 `-9223372036854775808` 至 `9223372036854775807`。
- **Float64**：按讨论中的 64 位二进制浮点数（binary64）设计，精度约为 15–17 位十进制有效数字，并非精确十进制数。
- 整数向浮点数提升不意味着所有 Int64 都能精确表示。大整数混合运算与混合比较的精度边界，仍需在后续规范中明确。
- 整数溢出不采用静默回绕，也不自动升级为大整数或浮点数。

| `3E-2` | 0.03 |
| `1.2e+4` | 12000.0 |

同时接受 `e/E` 和可选指数符号；带 `e/E` 的字面量统一识别为浮点数，因此 `1000` 与 `1e3` 的数值相同但类型不同。相关词法细则已按 D63 确认。

小数点两边必须有数字，`.5` 和 `1.` 分别须写成 `0.5` 和 `1.0`。首版不加入数字分隔符、十六进制或二进制字面量；不完整指数与数字粘连名称报错，范围规则见 D63。

### 3.4 除法与余数

普通 `/` 返回浮点结果，不对商进行整数取整。整数除法采用向下取整，即取不大于准确数学商的最大整数。

对于整数被除数 a 和非零整数除数 b，整数商 q 和余数 r 定义为：

```text
q = floor(a / b)    此处 a / b 表示准确数学商
r = a - q × b
a = q × b + r
```

非零余数与除数同号，且 `|r| < |b|`。除数为正时，`0 <= r < b`，符合正除数下常见的非负余数约定；除数为负时，`b < r <= 0`，余数可以为负。因此这套规则并不要求所有情况下余数都非负。

| 示例 | 结果 |
|---|---:|
| `5 / 2` | `2.5` |
| `4 / 2` | `2.0` |
| `5 // 2` | `2` |
| `-5 // 2` | `-3` |
| `5 // -2` | `-3` |
| `-5 // -2` | `2` |
| `5 % 2` | `1` |
| `-5 % 2` | `1` |
| `5 % -2` | `-1` |
| `-5 % -2` | `-1` |
| `-4 // 2` | `-2` |
| `-4 % 2` | `0` |

例如 `-5 = (-3) × 2 + 1`，而 `5 = (-3) × (-2) + (-1)`。整除时余数为 0，无需额外调整整数商。

整数除法与余数符号现已按 D62 确认为 `//` 与 `%`；单行注释使用 `#`，与整数除法符号区分。

上述整数商与余数规则严格适用于两个 Int64 操作数；浮点数参与 // 或 % 报类型错误，不自动截断（D64）。

实现时必须保留 Int64 的精度，不能先转换为 Float64 再取整来计算整数商，也不能直接照搬宿主 C++ 的负数整数除法和余数结果。除零和整数商超出 Int64 范围仍按第 3.5 节报错。

### 3.5 数值错误

已确认下列运算应报错：

- 普通除法、整数除法、取余的除数为零。
- Int64 运算结果超出允许范围，包括最小 Int64 除以 `-1` 得到的整数商超出范围。
- 浮点运算产生无穷大或 NaN，例如有限浮点数相乘后溢出。
- 浮点数显式转整数时，向零截断后的结果超出 Int64 范围（D19）。

例如 `10 / 0`、`1e308 * 1e308` 应报告数值错误。MYB 需要落实自己的检查规则，不能直接沿用宿主 C++ 的异常或未定义行为。

错误诊断的路径、1 基行列、类别、原因及适用的 MYB 调用栈已按 D68 确认；首版运行错误立即停止，不提供通用用户异常捕获。具体退出码、诊断完整格式与资源限制仍待收口。

普通浮点舍入误差不视为异常。浮点字面量允许舍入和下溢，包括舍入为 0.0，溢出为无穷大时报错（D63）。运行中浮点算术同样允许舍入与下溢归零，除零和非有限结果仍报错（D64）；D65 确认拒绝非有限数值字符串，负零显示为 -0.0，显示约定详见第 3.51 节。

### 3.6 字符串编码、长度与索引

索引和切片的求值/检查时机、严格 Int64 下标及显式端点、null 不代表省略已按 D69 补充，详见第 3.55 节。

Unicode 码点是字符的编号，UTF-8 是将码点编码为字节的方式。MYB 内部使用 UTF-8，面向程序的字符串长度与索引以码点为单位。索引语法见 D62，len 接口见 D58：

| 字符串 | 码点长度 | UTF-8 字节数 |
|---|---:|---:|
| `"ABC"` | 3 | 3 |
| `"北邮"` | 2 | 6 |
| `"A北😀"` | 3 | 8 |

索引应取得一个完整码点对应的字符串，例如 `"北邮"[0]` 得到 `"北"`，而不是其编码的单个字节。正向下标从 0 开始，负下标从末尾计数，因此 `"北邮"[-1]` 得到 `"邮"`。长度为 n 时，有效整数下标范围为 `-n <= i < n`；负下标 i 换算为 `n + i`，越界访问报错。空字符串没有有效下标。数组也采用相同的单个索引规则（D24），但数组按元素计数，字符串按码点计数。

已确认采用类似 `s[start:end]` 的切片语法，按码点截取并返回字符串。左闭右开区间已确认（D25），包含 start 位置、不包含 end 位置。普通切片允许省略端点、负端点及越界截取有效范围（D26），细则见第 3.18 节；首版不支持步长与反向切片（D27）。单个索引越界仍报错。

**码点不等于视觉上的完整字符（字素簇）。**组合重音字母或组合 emoji 可能包含多个码点，因此显示为一个图形时，MYB 的长度也可能大于 1。首版不按完整字素簇索引；字符串按实际码点保存，不自动进行 Unicode 规范化（D63）。

字符串转义和源码中无效 UTF-8 的处理已按 D63 确认；read_line 的 UTF-8 输入、编码/读取失败报错规则见 D65；文件文本接口已按 D66 确认，其他终端接口仍须另行设计。

### 3.7 字符串不可变

已确认采用不可变字符串。不能通过索引赋值修改原字符串；替换、拼接等改变内容的操作应返回新字符串，已有字符串的内容保持不变。具体操作是否纳入首版、函数名称和语法仍待定义。

不可变性约束字符串内容，不要求每次赋值都复制底层字节。按修订后的 D17，当前绑定字符串的变量可以改为绑定另一个字符串，也可以改为绑定整数等其他类型的值；原字符串内容不会因此改变。运行时内存管理和存储共享策略仍需分别设计。

用户在确认 D25 后，基于 C++ 使用习惯询问“字符串也是字符数组，为何创建后不能改变”，并在解释后明确决定保留不可变字符串。采用不可变文本值时，文本处理函数返回结果，由调用者决定是否重新绑定变量，可减少通过共享对象修改文本带来的影响。代价是反复构造新字符串可能导致分配和复制；上层可采用收集片段后拼接的方式，具体接口尚待设计。Unicode 并不要求字符串不可变，但 UTF-8 的变长编码意味着按码点替换可能需要移动后续字节，不能按固定字节槽理解。游戏棋盘建议用可变数组维护状态，再生成显示文本；数组嵌套、元素替换及拼接接口尚需确认。

### 3.8 代码块

D69 另行确认独立花括号块可作普通语句，创建词法作用域，结束 } 后不额外加分号；函数/结构仍只在文件顶层声明，详见第 3.55 节。

已确认使用花括号 `{ ... }` 表示代码块，不使用缩进或 `end` 关键字划定代码块边界。块级作用域已另行确认，见 D21；D62 确认单语句也必须保留花括号。简单语句的分号规则见第 3.9 节。

条件、循环和函数写法已按 D62 确认；print(value) 的单参数、换行、刷新与返回 null 行为现已按 D65 确认。

### 3.9 语句结束方式

独立代码块按 D69 以 } 结束，不额外加分号；它不改变简单语句必须以分号结束的规则。

已确认赋值、函数调用、返回等简单语句以分号 `;` 结束，换行不替代分号。表达式可在词法单元之间跨行书写；这不意味着字符串字面量等词法单元可以任意跨行。

以下演示简单语句的结束方式，假设 `name` 已声明；print 接口见 D65：

```text
name = "MYB";
print(name);
```

D62 确认函数/结构定义、条件分支及循环以代码块结束；D64 进一步确认不提供空语句，块后不额外加分号。作为表达式使用的结构构造仍随所属简单语句加分号。

### 3.10 变量显式声明

已确认变量须显式声明，赋值操作不会自动创建变量。给未声明的名称赋值时报错，有助于发现赋值目标中的拼写错误。显式声明不要求写出类型，MYB 仍采用动态类型。

声明关键字现已按 D62 确认为 `let`：

```text
let score = 60;
score = 90;
scroe = 100;    此处假定 scroe 从未声明，应报错
```

允许先声明、后初始化，见 D20 和第 3.14 节；块级作用域已确认，见 D21。词法作用域已确认（D46）；允许内层遮蔽、禁止同一作用域重复声明已确认（D47）；局部变量从声明处生效已确认（D49）；初始化表达式中的同名名称指向新绑定已确认（D50）；声明关键字已按 D62 确认；未声明名称在实际读取或按既定顺序定位赋值目标时检查，诊断基础规则见 D68。已声明变量允许重新绑定不同类型，见第 3.11 节。

### 3.11 动态类型与重新绑定

值有类型，变量不固定为首次初始化值的类型。对已声明变量赋值时，将其绑定到右侧表达式求得的值；新值可以与旧值类型不同。赋值本身不因这种类型差异报错，后续运算按当前值检查操作是否有效。

以下使用已确认的 `let` 写法，各行结果为说明文字：

```text
let value = 60;      当前值为 Int64
value = "优秀";      允许，当前值改为 String
value = 2.5;         允许，当前值改为 Float64
value = 10 + "2";    右侧运算类型不匹配，报错
```

该选择不要求完整静态类型检查器，不承诺提前发现未执行路径中的类型错误。未声明的名称仍不能直接赋值；显式声明与动态重新绑定是独立的规则。

数组混合类型见 D23，函数参数绑定见 D31，结构固定字段名及运行时字段类型检查见 D32、修订后的 D33；返回规则见 D43，固定数量的位置参数见 D44，其他调用细则仍须分别设计，不能把本条关于变量重新绑定的决定自动扩展到所有容器和接口。

### 3.12 普通赋值与数值转换的区别

旧 D18 的固定类型变量赋值转换规则已废止。普通赋值保留右侧表达式结果的类型，不根据变量的旧值转换新值。

以下以暂定语法示意，各行结果为说明文字：

```text
let price = 1.5;
price = 2;           允许，当前值为 Int64 的 2
let count = 2;
count = 2.5;         允许，当前值为 Float64 的 2.5
count = int(2.5);    显式转换后，当前值为 Int64 的 2
let total = 1 + 2.5; 混合算术提升，结果为 Float64 的 3.5
```

混合算术中的整数向浮点数提升仍有效（D04），数字与字符串之间仍要求显式转换（D02）。整数转浮点数可能产生舍入，不能声称所有 Int64 均可精确表示。浮点数显式转整数的取整与范围规则见第 3.13 节；int/float/str 等基础转换接口已按 D65 确认。

### 3.13 浮点数显式转整数

对有限浮点值向零截断，去掉小数部分；截断后的整数须在 `-9223372036854775808` 至 `9223372036854775807` 范围内，否则报转换范围错误。不采用回绕或将超范围值钳制为最大/最小整数。

int(value) 名称已按 D65 确认，以下展示浮点转整数规则：

| 示例 | 结果 |
|---|---:|
| `int(2.7)` | `2` |
| `int(-2.7)` | `-2` |
| `int(2.0)` | `2` |
| `int(-0.7)` | `0` |
| `int(1e20)` | 范围错误 |
| `int(-1e20)` | 范围错误 |

整数除法与显式转换采用不同规则：`-5 // 2` 得到 `-3`，而 `int(-2.5)` 得到 `-2`。前者向下取整，后者向零截断，不能混用。`//` 已按 D62 确认为整数除法符号。

实现转换时须先检查范围，再执行宿主语言的整数转换，不能依赖 C++ 对超范围浮点数强制转换的行为。边界用例应按 Float64 实际可表示的值设计，避免把已经舍入为 `2^63` 的数误判为合法 Int64。

### 3.14 延迟初始化

允许声明变量而不提供初始值。此时变量处于“未初始化”状态，没有可读取的值；执行时首次赋值建立值绑定，之后按修订后的 D17 允许重新绑定不同类型。首次赋值前读取变量，在运行时报错。

未初始化状态不是一个供 MYB 程序正常读取的 null、0 或空字符串。Null 已另行确认（D41），显式赋值为 null 表示已初始化且明确没有值，不能用 null 代替未初始化读取错误。声明关键字为 `let`，见 D62。

不同执行路径可以为同一个变量赋入不同类型的值；后续赋值不会因先前分支所赋值的类型而受到限制。每次读取和运算仍须检查当前是否已初始化、当前值是否支持所需操作。

### 3.15 块级作用域

D69 确认独立块语句复用本节作用域规则，块外不可读取其临时名称，外层赋值及仍被引用的对象保留；函数参数与函数体最外层共用作用域的 D51 不变。

代码块内声明的局部变量，其可见范围限制在该块及其内部；块外不能访问该局部名称。需要在块外使用的变量，应声明在相应的外层作用域，再在内部块中赋值。给外层已声明变量赋值与在当前块声明新变量是不同操作。

该规则限制名称的可见范围，不直接规定对象何时释放。词法名称查找已确认（D46）；允许内层同名声明（遮蔽）、禁止同一作用域重复声明已确认（D47）；局部声明之前可查找外层同名绑定，没有则报未声明（D49）；初始化表达式中的同名名称指向新绑定，读取时报未初始化错误（D50）。

显式声明建立名称及其所属作用域；动态类型决定该名称之后可绑定不同类型的值。两者相容，不要求在声明时写出类型或固定类型。用户对显式声明提出疑问，但尚未撤销 D16。

### 3.16 可增长数组

首版数组允许通过增删元素改变长度，可用于逐条收集数据和维护增长的蛇身。固定尺寸的棋盘可通过创建所需元素并在应用中保持长度来表达；这不等于语言提供了强制固定长度的独立数组类型。

追加、插入、删除接口及嵌套数组已确认（D58）。普通下标访问或赋值越界报错、不通过越界赋值扩展数组已确认（D24）。数组允许混合类型（D23），普通切片及浅拷贝见 D25–D28，普通赋值共享对象见 D29，参数绑定见 D31；遍历时已有元素的替换见 D55。

用户在比较混合类型与同类型约束后，选择允许混合类型（D23）。例如暂定写法 `[10, "hello", 2.5]` 可以表示一个包含 Int64、String、Float64 的数组；不会因为混放而自动将整数转换为浮点数或字符串。将取出的整数和字符串相加仍按 D02 报错。空数组不需要通过首次加入的元素锁定元素类型；数组字面量和操作接口的最终语法仍待确定。

此前已解释：容器限制元素类型在技术上可以与变量动态改绑共存，但会增加空数组类型确定和写入约束等规则。用户选择 A 是采用更灵活的容器规则，不应记录为“动态类型必然禁止同类型容器”。

### 3.17 数组单个索引

D69 补充：先保留数组并求下标，再检查严格 Int64 类型及范围；n 取该原对象在下标表达式成功求值后的当前长度，详见第 3.55 节。

数组长度为 n 时，有效整数下标范围为 `-n <= i < n`；负下标 i 映射到 `n + i`。空数组没有有效下标。示例 `a = [10, 20, 30]` 中，`a[0]` 为 10，`a[-1]` 为 30，`a[-3]` 为 10；`a[3]`、`a[-4]` 越界，`a[3] = 40` 也报错，不自动追加元素。这与字符串的索引范围一致，不意味着数组内容不可变。

字符串和数组现已统一采用左闭右开的切片 `value[start:end]`（D25），包含 start 位置、不包含 end 位置。例如 `"ABCDE"[1:4]` 得到 `"BCD"`，`[10, 20, 30, 40][1:3]` 得到元素序列 `[20, 30]`。普通端点规则见 D26 和第 3.18 节，首版不支持步长或反向切片（D27）；数组切片采用浅拷贝（D28），首版不提供切片赋值（D64）。

### 3.18 普通切片端点规则

D69 补充：先保留接收对象，再依次求显式起止端点，全部成功后检查并取得该原对象的当前长度 n；显式端点严格 Int64，null 不表示省略，详见第 3.55 节。

用户已确认方案 A（D26），适用于字符串与数组的 `value[start:end]`：

1. 省略起点时使用 0，省略终点时使用序列长度 n。
2. 显式负端点先加 n，从末尾计算。
3. 将换算后的端点分别限制在 `[0, n]` 内，越界区间仅截取实际存在的部分。
4. 处理后起点不小于终点时返回空序列，不自动反向遍历。

例如 `"ABCDE"[:3]` 得到 `"ABC"`，`"ABCDE"[-2:]` 得到 `"DE"`，`"ABCDE"[1:100]` 得到 `"BCDE"`，`"ABCDE"[-100:3]` 得到 `"ABC"`，`"ABCDE"[10:20]` 和 `"ABCDE"[3:1]` 均得到空字符串。空序列的普通切片仍为空序列。数组遵循相同的端点处理，但以元素计数。

单个索引仍按 D12、D24 越界报错。这不表示浮点下标等非法端点类型也应被截断接受，不自动批准步长或切片赋值。计算负端点和截断边界时，解释器须避免宿主整数溢出。

用户已选择首版只提供普通连续切片（D27）。带第二个冒号的步长切片，包括 `s[::1]`、`s[::2]`、`s[::-1]`，均不属于首版语法，应报告不支持的语法而不是忽略步长。`s[-2:]` 仍合法，因为负端点仅用于从末尾定位；`s[3:1]` 仍返回空结果，不反向遍历。反转与间隔取样可通过循环或未来库函数表达，尚未承诺专门的内置接口。

### 3.19 数组切片采用浅拷贝

用户已选择 A，并明确指定浅拷贝（D28）。每次数组切片创建新的外层数组，包括完整切片 `a[:]` 和结果为空的切片。新数组的元素槽位与长度独立；替换元素、追加或删除元素不改变原数组的槽位或长度。

浅拷贝不递归复制内部对象。若元素是可变数组或可变结构，结果中的对应元素仍指向同一个内部对象，对该内部对象的修改可以从两边观察到。嵌套数组及结构实例元素已确认（D58），结构共享见 D34；切片不会递归复制此类对象。不可变字符串可以安全共享其内容，无需承诺复制底层字节。

语法示例：`let a = [10, 20, 30]; let b = a[:]; b[0] = 99;` 之后，a 仍为 `[10, 20, 30]`，b 为 `[99, 20, 30]`。切片复制的是选中元素本身的值或对象引用，不对不同类型做隐式转换，不作为共享原数组元素槽位的视图。

### 3.20 普通数组赋值与统一的绑定模型

用户已确认普通数组赋值采用 A（D29）：`b = a` 让 b 绑定 a 当前绑定的同一个数组对象，不自动复制。通过任何一个绑定修改这个数组的元素或长度，另一绑定均可观察到；重新给 b 赋值只改变 b 的绑定，不修改数组或 a 的绑定。

示例：`let a = [10, 20]; let b = a; b[0] = 99;` 后，两者观察到 `[99, 20]`；随后 `b = [7, 8];`，a 仍为 `[99, 20]`，b 则绑定新数组 `[7, 8]`。需要独立的外层数组时使用 `b = a[:]`，按 D28 浅拷贝。

用户担心这与其他设计决定不一致。当前规则可用三个操作统一理解：名称赋值建立或更新值绑定；数组元素赋值修改对象内容；切片求值得到新的序列结果，数组结果明确浅拷贝。字符串不可变意味着不提供原地修改文本内容的操作，不妨碍变量重新绑定字符串。该模型不要求数值在底层也采用堆对象和指针，具体存储由解释器实现决定。

这套选择支持动态改绑和显式复制，但确实引入共享可变状态：给数组起第二个名称并非获得快照，浅拷贝也不是完整的游戏状态备份。文档、示例和测试需要区分绑定变化、外层修改和内部对象修改，不能把“自洽”误写为“没有意外修改风险”。

函数参数现已确认沿用同样的绑定模型（D31）：调用时为形参建立独立的局部绑定，绑定实参表达式求得的值。接收数组时共享对象，不隐式浅拷贝或深拷贝；修改数组内容可被调用方观察到，重新给参数赋值不改变调用方变量的绑定。参数声明本身建立局部名称，不要求调用者额外写 `&`；函数声明采用 `fn name(params) { ... }`，见 D62。

函数示例 `fn change(items) { items[0] = 99; items = [7, 8]; }`，对数组 `[10, 20]` 调用后，调用方仍绑定原数组，其内容为 `[99, 20]`。若传入数值或不可变字符串，重新给参数赋值同样只更新局部绑定。需要隔离数组修改时，调用方可以显式传入切片浅拷贝或深拷贝函数的结果，具体隔离程度遵循各自复制规则。

此模型是共享对象、独立变量绑定，不等同于 C++ 的引用参数 `T&`，也不要求数值在底层以指针存储。结构实例现已确认采用同样的共享规则（D34）。返回值基础规则已确认（D43）；固定数量的位置参数及数量不匹配报错已确认（D44），首版不提供默认参数、命名参数或可变参数。

### 3.21 显式深拷贝函数与实现分工

用户确定通过专门函数显式进行深拷贝（D30），由应用决定何时支付复制开销。具体接口采用 `deep_copy(value)`，当前类型范围、重复引用与循环处理已确认（D59，第 3.45 节）；未来新增值类型的复制支持、资源限制与错误诊断仍须另行明确，不应宣称已实现。

用户已明确选择 A：通用深拷贝作为宿主内置函数，由解释器运行时实现，MYB 程序通过普通函数调用使用；函数体不要求用 MYB 编写。这便于识别值类型和对象身份、分配新数组或结构，并维护已复制对象的映射。宿主技术路线本身仍未定稿，不因这一决定自动确认 C++。无需引入新的语法、先实现包管理器或任意外部函数接口，也不必先向 MYB 程序暴露所有运行时内部机制。

MYB 也可以编写针对特定数据布局的复制函数，例如逐行复制一个只包含不可变数值的棋盘；但通用深拷贝需要处理更多类型和对象关系。标准库是语言提供的一组接口，不要求所有函数都用 MYB 自身实现：部分可由宿主提供，部分可以用 MYB 编写并调用这些基础能力。文件与终端操作需平台底层支持；深拷贝主要依赖运行时对象模型，不属于平台适配操作。

实现分工已澄清：用户此前“采用宿主内置函数，用 MYB 实现”的表述，已通过“我想表达的就是 A”明确为宿主实现、MYB 调用。函数传参模型也已确认（D31，第 3.20 节）；深拷贝接口语义见 D59。该选择不代表批准全部标准库接口或已完成实现。

### 3.22 命名结构与固定字段集合

用户已选择 A（D32）：先声明结构名称及固定字段名集合，例如坐标 Point 的 x/y、成绩记录的 name/score，之后创建实例。实例不能在运行时临时增加或删除字段。结构类型定义与实例是不同层次，类型描述字段集合，实例保存具体的字段值。

字段现已要求显式声明类型（修订后的 D33），此前未标类型的 `struct Point { x; y; }` 不再作为当前结构声明建议。结构声明采用 `struct Point { x: Int64; y: Int64; }`，实例构造采用 `Point { x: 3, y: 5 }`，字段使用点号访问；类型标注与标点已按 D62 确认，按名称构造沿用 D36。构造时漏填、重复或填写未知字段均报错（D37），具体诊断格式和定位细则仍待设计。该选择不意味着已采用方法、继承、访问权限等完整类机制，也不将结构体自动视为 C++ 的值拷贝对象。

用户在担心坐标误写为字符串、比较 Python 类型标注与运行时校验后，明确将 D33 修订为字段显式声明类型，由解释器在创建实例和每次字段写入时检查。此前“字段可改存任意类型”的规则已被替代，不能继续作为有效决定。

例如 Point 的 x/y 都声明为 Int64 时，`let p = Point { x: 3, y: 5 }; p.x = 4;` 合法；`p.x = "east";` 在写入时报告类型错误，x 保留原值 4；`Point { x: "east", y: 5 }` 在创建时即报错，不能成功产生不符合字段约束的实例。普通变量 `p = "完成";` 仍合法，它只改变 p 的绑定。不能通过给未知字段赋值临时新增字段，例如 Point 未定义 color 时，`p.color = "red"` 应报错。

字段类型约束来自结构声明，不按首次写入值推断或锁定。字段值可以在约束内更新；检查为运行时检查，不要求完整静态类型检查器，也不是仅供工具使用的提示。数值字段转换见 D35；Array 字段不约束元素类型、命名结构字段接受对应类型实例见 D38；可空字段见 D42；结构类型预登记、前向引用及递归声明见 D60。失败写入不替换目标字段，不承诺回滚求值右侧表达式已经产生的其他副作用。

用户已选择数值字段兼容方案 A（D35）：创建实例和后续写字段采用同一规则。Float64 字段接受 Int64 值，自动转换为 Float64 后保存，例如 `player.speed = 2;` 保存 2.0。Int64 字段不隐式接受浮点值，`player.x = 2.7;` 和 `player.x = 2.0;` 都报错；须先显式调用转换函数，按 D19 向零截断且检查范围。数值字段不自动解析字符串，例如写入 `"2"` 报错。Int64 提升为 Float64 可能损失大整数精度，与 D04 的数值提升限制一致。

该转换由字段声明的类型决定，不恢复已废止的 D18：普通变量 `let value = 1.5; value = 2;` 最后仍绑定整数 2。数值字段以外的类型兼容规则尚未由 D35 确认。

用户同时担心这一修订破坏“标签与对象”的模型。统一解释是：普通变量是可自由改绑的名称；字段是对象提供的、有声明约束的存储位置。`p = value` 更新名称绑定，`p.x = value` 请求修改 Point 对象中的 x 位置，须遵守对象的字段契约。约束写入不要求复制对象，也不决定对象是否共享；该方案增加了受约束字段这一概念，但不否定动态变量或独立参数绑定。共享规则已另行确认，见 D34。

用户已选择 A（D34）：结构实例的普通赋值与传参沿用数组的共享模型。`let q = p; q.x = 9;` 修改同一个实例，p 也观察到 x 为 9；重新给 q 赋另一个实例只改变 q 的绑定，不修改原实例或 p 的绑定。函数参数同样共享实例，重新给参数赋值只改变局部绑定。不采用自动复制外层字段的方案。

示例：`fn move_right(pos) { pos.x = pos.x + 1; }`，对 `head = Point { x: 3, y: 5 }` 调用后，head.x 为 4；函数内若随后执行 `pos = Point { x: 0, y: 0 };`，head 仍绑定原实例。通过任何绑定写入 `pos.x = "east";` 都须按 D33 报类型错误，不因共享绕过字段检查。`let backup = head;` 不构成备份，需要独立备份时显式调用深拷贝函数；其接口、支持范围与对象图规则仍待设计。结构的显式浅拷贝接口也未确定，不把数组切片语法直接扩展给结构。

### 3.23 按名称构造与扩展方向

用户已选择首版方案 A（D36）：创建结构实例时按字段名称填写，写作 `Point { x: 3, y: 5 }`（D62）。字段名决定值的归属，不依赖字段声明顺序；此前 `Point(3, 5)` 仅为讨论示意，已不作为首版构造方案。此决定不自动引入普通函数的命名参数。构造标点已按 D62 确认；字段按构造源码顺序求值与检查的规则已按 D64 确认，诊断细则仍待运行契约收口。

用户明确要求语言具备扩展能力。落实这一要求的设计建议是：保留现有写法及含义，后续新增能力尽量作为可选功能加入；不能保证任意新功能都天然兼容。候选扩展包括字段默认值、返回结构实例的普通工厂函数，以及将来有实际需求时的其他构造入口。这些不是首版功能承诺，也不自动引入构造函数重载、类或继承。

解释器架构阶段建议把解析得到的字段名与表达式、字段完整性检查、类型检查与数值转换、实例创建分开组织，复用 D33/D35 的检查规则；未来默认值或其他构造入口也应通过这些检查。当前仅记录设计方向，不选定具体模块或实现方案。

用户已进一步选择“首版使用 A”（D37）：创建实例时，声明的所有字段必须各填写一次；漏填、重复填写、填写未知字段均报错，首版不提供字段默认值。例如 `Point { x: 3, y: 5 }` 合法，`Point { x: 3 }` 因缺少 y 报错；不隐式填入 0、空字符串或空值。成功创建的实例应具备完整且满足类型约束的字段。该要求不改变普通变量允许延迟初始化的 D20，也不妨碍以后设计默认值扩展。

### 3.24 数组与结构实例作为字段值

用户已选择 A（D38）：结构字段可以存放数组或另一个结构实例。例如声明 `struct Player { name: String; position: Point; inventory: Array; }`，可按名称构造 `Player { name: "Alice", position: Point { x: 3, y: 5 }, inventory: ["钥匙", "药水"] }`。

`position: Point` 要求字段值为 Point 实例；另一个结构即使也有 x/y 字段，也不自动符合 Point 约束。`inventory: Array` 只要求字段值是数组，不限制元素类型：`player.inventory = 123;` 报错，`player.inventory[0] = 123;` 在下标有效时允许。此规则沿用混合类型数组 D23，不引入 `Array[Point]` 等元素类型约束语法。

创建实例或更新字段时，把已有数组或结构实例作为值写入会共享该对象，不自动浅拷贝或深拷贝。例如 `let pos = Point { x: 3, y: 5 };` 后，将 pos 写入 player.position，再执行 `pos.x = 9;`，player.position.x 也为 9。重新将 player.position 设为另一个 Point 实例只更新该字段，不改变 pos 的绑定；写入时仍遵守字段类型检查。

结构组合见 D38，可空字段见 D42，数组嵌套见 D58，循环对象图和深拷贝见 D59。类型声明顺序、前向引用、自递归/互递归字段类型已另行确认（D60），不把对象图支持与类型声明规则混同。

### 3.25 布尔值与条件判断

用户已选择 A（D39）：MYB 引入独立的 Bool 类型，用 `true`、`false` 表示真假；合法比较表达式产生 Bool。条件分支与条件循环（if/while）的条件必须求得 Bool 值，否则在运行时报类型错误。该规则不要求完整静态类型检查器，也不改变普通变量允许动态改绑的 D17。

示例：`if (score > 100) { ... }` 合法，`if (game_over) { ... }` 在 game_over 当前绑定 Bool 时合法。若 score 为整数，则 `if (score) { ... }` 报错；若 items 为数组，则 `if (items) { ... }` 报错。需要非零或非空判断时显式写 `score != 0` 或 `len(items) > 0`（len 已按 D58 确认）。即使是数值 0/1、空字符串或空数组，也不能直接用作条件。

例如 `let game_over = false; game_over = "false";` 中，重新绑定字符串仍合法；随后将 game_over 用作条件时才报告类型错误，不将该字符串解释为真或假。普通变量的未初始化读取仍先按 D20 报错，未初始化状态不是 false。

逻辑运算的类型约束及短路已确认（D40），相等比较的类型兼容与对象身份规则已确认（D56），大小比较及 Bool 不参与算术已确认（D57）。条件写法与逻辑符号已按 D62 确认；完整优先级见 D64，int/float 拒绝 Bool（D65），额外 Bool 专用转换接口未确认；Null 已另行确认，见 D41。

### 3.26 逻辑运算与短路求值

用户确认采用这套规则（D40），与、或、非符号现已按 D62 确认为 `&&`、`||`、`!`；完整优先级已按 D64 确认。

- `a && b`：先求 a 并检查其为 Bool；a 为 false 时直接返回 false，跳过 b；否则求 b 并检查其为 Bool，返回该布尔值。
- `a || b`：先求 a 并检查其为 Bool；a 为 true 时直接返回 true，跳过 b；否则求 b 并检查其为 Bool，返回该布尔值。
- `!a`：求 a 并检查其为 Bool，再取反。实际求得非 Bool 操作数时报告运行时类型错误，不做隐式真值转换。

例如 `divisor != 0 && total / divisor > 10` 在 divisor 为零时跳过除法；`len(items) > 0 && items[0] == "钥匙"` 在数组为空时跳过索引访问（len 已按 D58 确认）。被跳过的函数调用不会打印或修改数据，因此必须执行的操作应单独写成语句。

短路也跳过右侧的运行时类型检查：`false && 123` 得到 false，`true && 123` 报类型错误；这不表示整数可作为逻辑操作数，而是前者根本未求右侧。所有表达式仍须通过语法分析，短路不隐藏语法错误。结果始终为 Bool，不返回任意类型的操作数值。该决定不引入按位运算、空值合并或完整静态类型检查。

### 3.27 Null 与未初始化状态

用户已选择提供 Null（D41），以 `null` 表示明确的“没有值”，例如当前没有目标、查找没有结果。普通变量可以绑定 null，之后仍能按 D17 改绑其他类型；混合类型数组可以保存 null。函数可以将 null 作为普通值传递；无显式返回值时也返回 null（D43），相关关键字写法见 D62。

`let target;` 仍是未初始化，读取时报错（D20）；`let target = null;` 已完成初始化，可以读取、传递和判断。null 不等于 0、false 或空字符串，也不表示空数组。允许使用 `target == null`、`target != null` 判断是否缺少值，产生 Bool；null 与 null 相等，与非 Null 值不相等，不做隐式类型转换。该约定不自动决定其他类型之间的相等规则。

null 不能直接参与算术，不能对其索引或访问字段；执行这些操作应报告运行时错误。`if (target)` 在 target 为 null 时按 D39 报类型错误，应显式写 `if (target != null)`。操作符和条件语法仍按当前讨论示意。

引入 Null 不使所有带类型字段自动接受 null；字段默认不可空、须显式声明才允许 null（D42），也不改变 D37 的构造时必须填写全部字段。函数无显式返回时返回 null 已确认（D43）；D65 确认 str(null) 和直接显示 null 使用文本 null；int/float 及只接收 String 的尝试解析接口拒绝 Null 参数。

### 3.28 显式可空字段

用户确认采用字段默认不可空、显式声明后才允许 null 的规则（D42）。可空声明写作 `T?`，问号语法已按 D62 确认。例如 `struct Player { position: Point; target: Point?; }` 表示 position 必须为 Point 实例，target 可以为 Point 实例或 null。

创建时仍须填全字段，例如 `Player { position: Point { x: 3, y: 5 }, target: null }`；省略 target 仍按 D37 报错，不隐式补 null。之后 `player.position = null;` 在写入时拒绝，原字段保留；`player.target = null;` 允许；`player.target = 123;` 因不满足 Point 或 Null 的约束而拒绝。

可空声明仅在原有类型约束上增加 null 这一可能，不放宽其他值的检查；例如可空数值字段的非 null 写入仍遵循 D35，Array? 的非 null 值仍须为数组，且数组元素继续允许混合类型。普通变量不因字段可空规则而获得固定类型，仍可绑定 null 或改绑其他值。

这在表达意图上借鉴显式区分可空与不可空的设计，但 MYB 在实例创建和字段写入时检查，不执行 Kotlin 式的静态空值流分析。若 player.target 当前为 null，直接访问 player.target.x 仍在运行时报错；程序可显式比较 null 后再访问，但解释器不提前证明所有访问都安全。可空与对象共享相互独立，不引入复制，也不据此确认递归类型、空值安全访问操作符或空值合并运算。

设计取向是：普通变量保持动态绑定，结构字段明确数据要求，缺失值须主动允许。该决定不引入完整静态类型检查器；函数无显式返回值时返回 null 已另行确认（D43）。

### 3.29 函数默认返回 null

用户在比较默认空值、无返回值与 void 方案后，选择类似 Python 的方案（D43）。MYB 沿用既定的 `null` 名称，不另行引入 `None` 值或别名。写法 `return value;` 结束当前函数并返回表达式求得的值；`return;` 或正常执行到函数末尾则返回 null。发生运行时错误不属于正常结束，不转换为 null。

调用者可以接收 null 结果，也可以将函数调用作为独立语句而忽略其返回值。例如函数 `fn move_right(player) { player.position.x = player.position.x + 1; }`，执行 `let result = move_right(player);` 后位置已更新，result 绑定 null。遗漏预期的 return 不因此报错，可能在后续使用 null 时暴露问题；这是所选方案的代价。

首版不引入 void 或函数返回类型声明，也不要求函数每条正常结束路径都显式 return。函数可以在不同调用或分支返回不同类型的值，例如 Point 实例或 null。此前“显式 void，其他函数必须提供返回值”的方案仅经过讨论，未采用。

当前只有结构字段具有声明的存值类型与可空约束。普通变量、函数形参可动态改绑，数组元素可改存不同类型，函数结果无固定声明类型；具体运算、条件与索引仍按实际值检查。将函数结果写入结构字段时仍须满足该字段约束，返回 null 不绕过不可空字段检查。固定数量的位置参数见 D44，顶层函数预登记与递归见 D45，返回可变对象不自动复制见 D61；参数写法已按 D62 确认。

### 3.30 固定数量的位置参数

用户确认首版用户定义函数采用固定数量的位置参数（D44）。例如声明 `fn move(player, dx, dy) { ... }`，调用 `move(player, 1, 0);` 合法，`move(player, 1);` 或 `move(player, 1, 0, 5);` 因参数数量不匹配报错，不补 null，也不忽略多余实参。D64 确认先检查调用目标与数量；不匹配时不执行实参、不进入函数体，通过后实参从左到右求值，不承诺回滚已发生的实参副作用。

固定数量不意味着固定类型。参数继续按 D31 建立独立局部绑定，可以重新绑定不同类型；数组与结构实参继续共享对象。首版暂不提供默认参数、按名称传参或可变参数声明，未来可另行扩展。结构实例按字段名称构造（D36）不改变普通函数按位置调用的规则。

需要处理数量不定的数据时，可以将数据放进一个数组作为单个实参，例如 `total([10, 20, 30]);`，其中 total 声明一个参数。宿主内置函数按各自签名调用：长度/数组操作见 D58，deep_copy 见 D59，print 等基础接口见 D65；这些接口不改变用户函数固定数量位置参数的 D44。

### 3.31 顶层函数、定义顺序与递归

用户确认首版采用顶层命名函数、执行前登记、支持递归和相互递归的方案（D45）。函数定义只能位于文件顶层，不能嵌套在其他函数、条件块或循环块中。此决定不自动确认函数可赋给变量、作为参数或返回值；一等函数及相关能力仍待单独设计。

程序执行前登记全部顶层函数，因此调用不受函数定义文本顺序限制，无须额外前置声明。示例 `let answer = factorial(5); fn factorial(n) { if (n <= 1) { return 1; } return n * factorial(n - 1); }` 合法，answer 为 120。函数可以调用自己，也可以通过其他函数间接调用自己；每次调用建立独立参数和局部绑定。调用深度限制及资源耗尽的诊断留待运行时设计，不承诺无限递归或尾调用优化。

登记函数不执行其函数体，不提前执行变量初始化。函数读取尚未初始化的变量仍报错；函数按词法作用域查找全局变量（D46）；局部声明的可见起点已确认（D49）；允许函数引用其定义位置之后的全局声明，但实际读取时须已声明并初始化（D52）。名称冲突与重名函数规则已另行确认（D61）；多文件机制仍待范围设计。

该选择服务于将主要流程与辅助函数自由排列的需求。嵌套函数与闭包不纳入首版，后续可另行设计扩展；结构类型的递归声明不由函数递归决定。

### 3.32 词法作用域与全局变量查找

用户选择词法作用域（D46），强调与全局变量逻辑一致。名称依据代码的作用域嵌套关系解析；函数内读取名称时，从当前块向本函数的外层块及参数查找，再到全局作用域，不进入调用者的局部作用域。未找到名称时报错；找到尚未初始化的绑定时按 D20 报错，不因读取失败转而查找其他绑定。

顶层函数访问的全局绑定不因调用者改变。例如 read_score 在顶层定义且读取全局 score，即使从 run 内调用，也不会因此读取 run 的局部 score。内外层同名声明现已允许，同一作用域重复声明则报错（D47）。调用者需要传递自己的局部数据时，可通过参数显式传入。

词法作用域决定名称对应哪个绑定，不固定绑定中的值类型，也不在函数登记时复制全局变量的值。函数提前登记（D45）不提前初始化变量。局部变量从声明处生效（D49），函数可以引用其定义位置之后的全局声明，实际读取时须已声明并初始化（D52）。赋值规则已另行确认（D48）：按词法作用域更新最近的已有绑定，可以直接更新全局绑定，无须额外 global 声明。

### 3.33 遮蔽、重复声明与赋值

用户确认允许内层遮蔽、禁止同一作用域重复声明（D47）。显式声明在当前作用域建立新绑定；若外层已有同名变量，内层绑定遮蔽该名称。对内层变量重新赋值仅更新内层绑定，离开内层块后外层绑定继续可见。

示例：`let score = 10; if (true) { let score = 20; score = 30; }` 执行后外层 score 仍为 10。如果内层没有声明，`let score = 10; if (true) { score = 30; }` 则更新外层已有绑定，块结束后 score 为 30。

同一作用域中 `let score = 10; let score = 20;` 报重复声明错误；需要修改原变量时写 `score = 20;`。允许动态改绑不代表允许重复声明，改绑时新值仍可以是不同类型。同名绑定独立也不表示对象自动复制；若两个绑定持有同一可变对象，修改对象内容仍遵循既定共享规则。

遮蔽提高局部命名的自由度，但可能让程序员误以为正在更新外层变量。局部声明可见起点已确认（D49）；初始化表达式中的同名解析已确认（D50）；参数与函数体最外层共用声明作用域已确认（D51）；变量与函数/结构/内置名称冲突的规则见 D61。函数内直接赋值全局变量已另行确认（D48），仍以最近的已有绑定为目标。

### 3.34 赋值与全局绑定

用户选择方案 A（D48）：赋值与读取采用同一词法名称查找路径，更新最近的已有绑定。全局绑定位于该路径最外层，可以在函数内直接重新赋值，无须额外 global 声明。赋值不查找调用者的局部变量，也不在名称不存在时隐式创建变量。

示例：`let score = 0; fn add_score(points) { score = score + points; } add_score(10);` 执行后全局 score 为 10。若函数内已声明 `let score = 100;`，其后的 `score = 200;` 更新局部 score，不改变全局绑定。直接给未初始化的已有绑定赋值可以完成初始化，但 `score = score + points;` 若需读取尚未初始化的 score，仍按 D20 报错。

该规则统一“声明创建当前作用域绑定，赋值更新已有绑定”的行为。代价是函数内漏写局部声明且全局恰好有同名变量时，可能意外改动全局状态。重新绑定变量和修改共享对象内容仍是不同操作，普通变量的赋值不引入复制；字段写入仍须满足字段声明约束。

局部声明之前同名名称按外层绑定解析，局部绑定从声明处生效（D49）；初始化表达式中的同名解析已确认（D50）；参数与函数体最外层共用声明作用域已确认（D51）。本条不引入全局名称的专门限定语法；未声明名称的检查时机已另按 D68 确认为实际运行到读取或赋值目标定位时。

### 3.35 局部变量声明的可见起点

用户选择方案 A（D49）：局部变量从声明处开始生效，不把局部名称提前用于整个代码块。示例 `let x = 10; if (true) { print(x); let x = 20; print(x); }` 依次输出 10、20；第一个 x 对应外层绑定，第二个对应局部绑定。let 已按 D62 确认；print(value) 已按 D65 确认。

局部声明之前，读取或赋值同名名称均按当处可见的外层绑定解析；若没有可见绑定，则报名称未声明，不自动补 null，也不把后面的局部声明视为已存在。局部声明之后，遮蔽按 D47 生效。已经声明但尚未初始化的变量仍按 D20 禁止读取，不能回退读取外层同名变量。

该规则使一个块内声明前后的同名名称可能对应不同绑定，是选定方案的使用代价。函数提前登记是 D45 的单独规则，不推广为局部变量提前登记。声明自身初始化表达式的可见边界已另行确认（D50）：先建立新绑定，再计算初始值，因此 `let x = x + 1;` 因读取尚未初始化的新 x 而报错，不读取外层 x。函数访问其定义位置之后的全局变量已另行确认（D52），实际读取时须已声明并初始化。

### 3.36 初始化表达式中的同名名称

用户确认方案 A（D50）：处理变量声明时先在当前作用域建立新的未初始化绑定，再计算初始化表达式，成功求值后将结果存入新绑定。初始化表达式中的同名名称已对应新变量，不再对应外层同名变量。

示例 `let x = 10; if (true) { let x = x + 1; }` 在内层初始化时读取新 x，因其尚未初始化而报错，不得到 11，也不回退到外层 x。此处行为与先写 `let x;` 再写 `x = x + 1;` 的自我读取错误一致。不依赖宿主语言的未初始化读取行为，MYB 应明确诊断。

该规则与 D49 配合：声明之前的名称仍可解析为外层绑定；进入声明及初始化表达式后，新绑定开始遮蔽外层。读取未初始化绑定时报错是 D20 的延续。同一作用域重复声明仍按 D47 拒绝，不能借初始化语法绕过。

需要基于外层变量创建新值时可使用不同名称，例如 `let next_x = x + 1;`。D50 确定名称绑定与初始化的先后，不新增赋值表达式语法或错误后的继续执行机制，也不承诺回滚初始化表达式已产生的其他副作用。

### 3.37 参数与函数体的声明作用域

用户在比较其他语言及澄清 Python 参数改绑行为后，确认采用方案 A（D51）：函数参数与函数体最外层共用声明作用域。参数已经建立局部绑定，因此 `fn move(x) { let x = 10; }` 报重复声明错误；`fn move(x) { x = 10; }` 合法，更新形参的局部绑定。参数列表中的名称必须互不重复，例如 `fn move(x, x)` 报错。

函数内更深的块仍按 D47 允许遮蔽，例如 `fn move(x) { if (true) { let x = 10; } return x; }` 返回原参数绑定中的值，内层声明不改变它。内层若写 `let x = x + 1;` 则按 D50 读取未初始化的新变量并报错，不读取参数。

这与用户熟悉的 C++ 在这一重名问题上的使用效果相近，但不引入 C++ 的静态参数类型或引用参数语义。MYB 中 `x = "完成";` 仍可重新绑定形参，重新绑定只影响当前调用的局部绑定；修改共享数组或结构内容仍按 D31/D34 处理。允许参数改绑与禁止重复声明是两条不同规则。

### 3.38 函数引用后声明的全局变量

用户确认采用方案 A（D52）：函数允许引用写在其定义之后的全局变量，但实际执行到读取操作时，该全局变量必须已经声明并完成初始化。未声明时报告名称错误；已声明但未初始化时按 D20 报错；不自动填入 0、false 或 null。

示例 `fn get_score() { return score; } let score = 10; let result = get_score();` 合法，result 为 10。若在执行 `let score = 10;` 之前调用 get_score 并读取 score，则报未声明错误；若只执行过 `let score;` 而尚未赋值，则读取报未初始化错误。若全局变量已显式绑定 null，则它已初始化，可正常读取 null，后续操作再按实际类型检查。

变量声明及初始化仍按顶层语句执行顺序进行，函数登记不执行函数体或变量初始化。若初始化表达式间接调用函数读取正在初始化的全局变量，例如 `fn get_score() { return score; } let score = get_score();`，按 D50 该绑定已建立但未初始化，读取报错。

允许引用后声明名称不改变词法作用域：函数仍访问所属的全局环境，不访问调用者局部变量，不捕获定义时全局值的快照。规则约束的是实际读取时刻，不要求函数入口就检查所有可能访问的全局变量；未执行分支或短路跳过的读取不因此产生运行时读取错误。

函数赋值仍按 D48 查找已有绑定，不能因后面存在全局声明而提前创建它；已执行 `let score;` 后，可通过函数内直接赋值完成其初始化。名称冲突见 D61；名称读取或赋值目标不存在时按 D68 在实际执行时诊断，不要求提前拒绝未执行路径中的名称引用；多文件边界仍待设计。

### 3.39 分支与循环的首版范围

用户确认方案 A（D53）：首版提供条件分支 if/else if/else、条件循环 while、集合遍历循环 for … in …（具体写法见 D62），以及 break 和 continue。暂不增加 `for (初始化; 条件; 更新)` 形式的 C 风格循环；计数循环可以先通过 while 表达，后续可另行扩展。

集合遍历支持数组或字符串；字符串沿用码点规则，每轮得到由一个码点组成的字符串。break 退出当前所在的最内层循环，continue 跳过该循环当前轮的剩余部分并继续循环。条件仍只接受 Bool（D39），逻辑短路沿用 D40，代码块使用花括号（D14）。

具体关键字、括号与循环头声明方式已按 D62 确认；遍历期间禁止增删同一数组对象已确认（D54）。循环变量局部绑定、遍历表达式只求值一次、允许替换元素并读取未访问位置的最新值已确认（D55）；循环外控制语句诊断等仍须在规范中明确。确认此能力范围不自动引入 range 函数、通用迭代器协议、带标签的跳转或循环 else。

### 3.40 遍历期间增删数组的限制

用户比较 Python 列表与 C++ vector 的增删行为后，确认首版采用明确报错的方案（D54）：for … in … 遍历期间，禁止增删正在遍历的同一个数组对象。通过另一变量、结构字段或函数参数访问同一数组再增删，也不能绕过限制；检查依据对象身份，而非变量名称。

限制针对活动集合遍历。修改另一个独立数组不受此条影响；退出遍历后可以继续增删原数组。while 本身不设置这一禁令，可用于显式管理下标并增删，但若外层或其他尚未结束的 for … in … 正在遍历同一对象，限制仍生效。

需要遍历并增删原数组时，可以显式遍历 `values[:]`：切片创建独立的外层数组（D28），活动遍历针对该副本，增删原数组不会改变副本的槽位或长度。浅拷贝内部对象仍共享，不能把此方式解释为整个对象图的深拷贝。

该规则的收益是避免因元素移动而静默漏处理数据，代价是程序员需要选择显式复制或下标循环。增删操作应在改变数组之前拒绝，报错不替换目标数组内容；不承诺回滚此前其他操作的副作用。正常结束、break、return 或运行时错误离开遍历时，解释器须释放该次遍历的限制，不能让已退出的遍历继续限制对象。

本轮确认重点为增删限制，其余遍历规则已另行整体确认（D55，第 3.41 节），不把两项决定混同为同一次确认。

### 3.41 遍历对象、循环变量与元素替换

用户整体确认剩余遍历规则（D55）：进入 for … in … 时，遍历表达式只求值一次，循环保留并遍历得到的那个数组或字符串，不自动复制。之后重新绑定来源变量不切换当前遍历对象；显式传入切片才按 D28 得到浅拷贝结果。

循环变量仅在循环内部可见，每轮绑定当前元素值。重新赋值循环变量只改变其局部绑定，不替换原数组槽位；若当前元素是结构实例，循环变量共享该实例，修改其字段可被原数组观察到，仍须遵守字段约束。已有字符串和数组的共享、不可变规则保持有效。

遍历期间允许替换已有数组元素；尚未访问的位置在后续访问时读取其最新值。示例：`let numbers = [1, 2, 3]; for (let item in numbers) { if (item == 1) { numbers[1] = 20; } print(item); item = 0; }` 依次输出 1、20、3，原数组最终为 `[1, 20, 3]`。item 在循环外不可见；let 与 for 写法已按 D62 确认；print(value) 已按 D65 确认。

这不是元素快照：只保证增删受 D54 限制，不保证所有值在遍历期间不变。需要独立的外层元素快照时显式遍历浅拷贝；内部可变对象的隔离程度仍取决于是否请求深拷贝。

### 3.42 相等比较：基本值与对象身份

用户选择方案 A（D56），相等及不相等写作 `==` 和 `!=`：Int64/Float64 比较数值，String 比较内容，Bool 比较真假，Null 按 D41 仅与 Null 相等。Int64 与 Float64 可以数值相等，例如 `5 == 5.0` 为 true；除这对数值类型外，其他不同类型值不相等，例如 `true == 1` 和 `5 == "5"` 都为 false，不隐式转换。!= 为相等结果的取反，两者均产生 Bool。

数组与结构实例比较对象身份：`let a = [1, 2]; let b = a; let c = [1, 2];` 后，a == b 为 true，a == c 为 false，a == a[:] 也为 false。两个独立创建的 Point 实例即使字段相同也不相等；给现有实例建立另一个绑定则相等。比较不执行复制，也不递归比较元素或字段，不依据对象存储内容猜测身份。

内容比较可以通过普通函数明确表达，例如坐标相等使用 `head.x == food.x && head.y == food.y`。该选择使共享对象检查简单，但数组/记录内容比较需要程序员另写逻辑；不据此确认通用 deep_equal 内置函数。不可变字符串比较内容，不暴露其底层存储是否共享。

跨 Int64/Float64 的数值比较必须避免仅将整数转换为 Float64 造成的精度误判。例如整数 9007199254740993 与浮点值 9007199254740992.0 不应相等。浮点数比较其实际保存的数值，不自动采用近似误差阈值；近似比较可以由程序显式请求。大整数混合算术的舍入仍按既有数值规则，不因精确的相等判断而变成任意精度算术。

相等规则适用于当前已确定的值类型。首版函数不作为值使用（D61），不引入函数值相等比较；未来若扩展须另行设计。操作数表达式若读取未初始化变量或执行其他错误操作，仍报告该错误，不能把表达式执行失败变成 false。大小比较、字符串拼接和普通表达式求值顺序已另行确认（D57）。

### 3.43 大小比较、拼接与求值顺序

用户整体确认本组建议（D57）：数值支持 <、<=、>、>=，Int64 与 Float64 可以混合比较，并沿用 D56 对跨数值类型精度的要求，不能因先转换整数造成大小误判。

字符串按 Unicode 码点字典序比较，逐个比较首个不同码点；公共前缀相同时，较短字符串在前。此顺序不自动提供拼音排序、语言地区排序、忽略大小写或 Unicode 规范化。Bool、Null、数组和结构实例不支持大小排序；数值与字符串等不同类别之间排序报类型错误，例如 `3 < "4"` 报错，与 D56 中 `3 == "3"` 为 false 的相等规则区分。

`+` 支持数值相加或两个字符串拼接；其他组合报错，不自动将数值转换成字符串，也不引入数组拼接。Bool 不作为 0/1 参与算术，例如 `true + 1` 报错；int/float 拒绝 Bool 已按 D65 确认，额外 Bool 专用转换接口未确认。

普通表达式的操作数和函数实参从左到右求值，例如 `first() + second()` 先执行 first，再执行 second；`f(g(), h())` 先求 g，再求 h。逻辑与/或保留 D40 的短路，不因求值顺序规则执行本应跳过的右侧。若已执行的表达式报错，不再继续后面的求值，不承诺回滚先前副作用。

求值顺序不等于运算优先级；`1 + 2 * 3` 为 7。完整七层优先级/结合性、比较不链写、调用先检查目标与数量再求实参，以及普通赋值先右侧再定位左侧的规则已按 D64 确认，见第 3.50 节。

### 3.44 嵌套数组与基础操作接口

用户整体确认本组方案（D58）：首版数组可包含其他数组或结构实例。各内层数组仍是普通可增长数组，可以长度不同，不引入独立的二维数组类型。示例 `let board = [[0, 0, 0], [0, 0, 0]]; board[0][1] = 1;` 中，每行由独立数组表达，支持连续索引。

以下接口作为宿主内置函数提供，采用普通函数调用形式，首版不需要数组成员方法或完整类机制：

| 接口 | 操作 | 返回值 |
|---|---|---|
| len(value) | 接受数组或字符串，返回元素数或码点数 | Int64 |
| append(array, value) | 在数组末尾追加元素 | null |
| insert(array, index, value) | 在指定位置前插入，末尾位置表示追加 | null |
| pop(array) | 删除数组最后一个元素 | 被删除的值 |
| remove_at(array, index) | 删除指定位置的元素 | 被删除的值 |

接口的实参数量按表中签名固定，数组参数必须为数组，index 必须为 Int64，不接受 Bool、Float64 或字符串代替下标。pop 空数组报错；remove_at 按 D24 对已有元素的索引规则检查。insert 的负位置仍先加数组长度 n，再检查位置；接受负位置 -n 至 -1 和非负位置 0 至 n，其中 n 表示末尾，空数组只有位置 0 合法。不钳制无效位置，也不在越界时隐式填充元素。

所有操作沿用共享模型：增删修改同一个数组对象，追加/插入可变对象不自动复制；pop/remove_at 返回被移除元素的值或对象引用，不触发深拷贝。数组增删接口遵守 D54，通过任何别名增删活动遍历对象都报错。len 只观察长度，不受增删限制影响。数组替换与元素类型规则仍按 D23/D24/D55。

例如 `insert(snake, 0, next_head); let old_tail = pop(snake);` 可以表达加入新蛇头并移除蛇尾。允许循环对象图与深拷贝保留循环已另行确认（D59），循环对象显示已另行按 D65 确认：当前递归路径遇环显示 <cycle>；此规则独立于深拷贝映射。

### 3.45 deep_copy 的类型范围与对象关系

用户确认采用 Python 风格规则（D59），作为 MYB 固定的宿主内置接口 `deep_copy(value)`。首版对 Int64、Float64、Bool、Null、String 返回相同的值；不可变字符串可以复用底层存储，不要求无意义的字节复制。对 Array 和命名结构实例创建新对象，递归复制其中的可变对象，结构副本保留原结构类型及字段约束。

同次复制为每个原可变对象记录唯一对应的新对象，副本与原对象图中的可变对象隔离，同时保留副本内部的共享关系。例如 `let row = [1, 2]; let data = [row, row]; let backup = deep_copy(data);` 后，backup[0] == backup[1] 为 true，backup[0] == row 为 false；写 backup[0][0] = 9 会使副本的两处都观察到 9，原 row 仍为 [1, 2]。若要拆散共享关系，可分别请求复制，而不把打散共享作为 deep_copy 的默认行为。

允许数组与结构对象图出现自循环或间接循环，并在复制中保留关系。例如 `let a = []; append(a, a); let b = deep_copy(a);` 后，b == a 为 false，b[0] == b 为 true。复制时在递归访问成员前建立并记录新对象，重访原对象时复用对应副本，不无限递归。不依赖变量名称来判断已复制对象。

复制映射只解决复制过程中的重复访问；运行时仍须能管理循环对象的生命周期，不能把仅使用 shared_ptr 或仅提供复制映射视为完整的回收方案。具体对象管理、回收时机及资源限制留到解释器架构阶段设计；本条不选定宿主语言或回收算法。

借鉴 Python 的数据复制规则不引入 __deepcopy__ 等用户自定义复制钩子、反射或对外部资源的通用复制能力。当前支持范围是已确认的值类型；未来若引入函数值、文件句柄等类型，需要另行规定其复制行为。函数名称与参数数量固定为上述单参数接口；普通赋值及切片仍按 D29/D28，不执行隐式深拷贝。

### 3.46 结构声明的登记顺序与递归类型

用户整体确认本组方案（D60）：结构声明只允许出现在文件顶层，不能在函数或条件/循环块内部定义。程序执行前先登记全部结构名称，再检查各结构字段声明中的类型名称。因此字段可引用写在后面的结构，也允许字段引用自身或互相引用；登记不创建实例，不执行普通变量初始化。

例如声明 `struct Player { position: Point; } struct Point { x: Int64; y: Int64; }` 合法，不要求 Point 在 Player 前面出现。所有字段类型必须存在于已登记结构或已支持的基本类型中；重复结构名、结构内重复字段名、未知字段类型均报告声明错误。跨变量、函数、结构及内置名称的冲突规则已另行确认（D61）。

递归字段类型例如 `struct Node { value: Int64; next: Node?; }`，声明与可空标点见 D62。可先创建 `let tail = Node { value: 20, next: null };`，再创建 `let head = Node { value: 10, next: tail };`。递归描述允许保存另一同类型实例，不自动递归创建整条链；所有实例仍须填全字段，null 仍须通过可空声明主动允许。

递归类型与实际循环对象图不同：上述链没有环；之后在约束内重新写入字段可形成 D59 已允许的环。首版不增加默认构造、自动补齐字段、继承、类型推导或用户构造函数。登记阶段检查类型名称与声明合法性，实际字段值继续在创建及写入时检查。

非可空递归字段不会自动获得终止值。没有可满足全部必填字段的现有实例时，程序无法凭空成功构造该结构；不为此引入未初始化字段或延迟补字段的对象构造过程。具体诊断位置与表述留到规范和前端设计明确。

### 3.47 名称保护、函数使用与返回可变对象

用户整体确认本组首版规则（D61）：全局变量、函数、结构类型和内置名称不能重名。重名函数报错，不按参数数量或参数类型提供函数重载。函数、类型和内置名称不能被普通赋值覆盖，也不能被局部变量或参数遮蔽；普通变量之间的内层遮蔽仍按 D47 允许。结构字段拥有独立名称集合，字段叫 len 等名字不会占用或遮蔽对应的全局名称。

首版函数只通过名称调用，不作为普通数据值：不允许将函数赋给变量、作为实参传递或返回函数。本条不引入函数类型、匿名函数或回调机制。可变对象仍是可传递、可返回的普通值，普通变量和形参的动态改绑能力不改变。

返回数组或结构实例时传递该对象，不执行浅拷贝或深拷贝。例如 `let data = [1, 2]; fn get_data() { return data; } let result = get_data(); result[0] = 99;` 后 data 为 [99, 2]，result 与 data 绑定同一数组。需要隔离时显式调用 deep_copy。

函数内部创建的新对象也可以安全返回，例如 `fn make_board() { let board = [[0, 0], [0, 0]]; return board; } let game_board = make_board();`。函数结束只使局部名称结束可见，不让仍由调用者持有的返回对象失效。运行时应管理对象生命周期，不照搬宿主栈上局部对象的悬空引用行为。

本组限制保护调用与构造名称，减少首版接口种类，代价是暂不支持回调或替换内置函数。后续若有应用需求，可另行设计函数值与名称扩展；不把该方向自动纳入首版。

### 3.48 整体语法设计

2026-10-14，用户在澄清函数参数、返回值及逻辑符号后确认整体语法方案（D62）。本节统一此前示例中的写法，沿用已确认的类型、作用域、共享和错误规则。它是整体语法的已确认设计；源码与字面量已进一步按 D63 确认，表达式规则已按 D64 确认；正式 EBNF 与运行接口仍需继续收口。

#### 3.48.1 变量、赋值与语句结束

使用 `let` 显式声明普通变量，不标注类型；允许延迟初始化。普通赋值更新已有绑定，仍允许改绑不同类型：

```text
let score = 60;
score = 90;
score = "完成";

let result;
result = 42;
```

变量声明、赋值、函数调用、`return`、`break` 和 `continue` 等简单语句以 `;` 结束，换行不能替代分号。条件、循环、函数体均必须使用 `{ ... }`，即使只有一条语句也保留花括号。

函数定义、结构定义、条件分支和循环以对应代码块结束，不在结束的 `}` 后额外加分号（D64 不提供空语句）。结构实例和数组作为表达式使用时，所属简单语句仍须有分号，例如 `let p = Point { x: 3, y: 5 };`。

#### 3.48.2 函数定义与调用

使用 `fn` 定义顶层命名函数，形参以逗号分隔，调用时按位置传入固定数量的实参：

```text
fn add(a, b) {
    return a + b;
}

let result = add(2, 3);
```

参数不声明类型，返回值也不声明类型。调用时形参绑定实参的实际值，执行具体操作时按值的类型检查；这与普通变量动态绑定的规则一致。`return value;` 返回该值，`return;` 或正常执行到函数末尾返回 `null`。返回数组或结构实例保持对象共享，不自动复制。

本节不改变 D44/D45/D61：参数数量固定，函数仅在顶层定义并预登记，支持递归，首版函数不作为普通数据值使用。

#### 3.48.3 结构声明、可空字段与实例构造

使用 `struct` 声明顶层结构，字段格式为 `字段名: 类型;`，每个字段声明以分号结束：

```text
struct Point {
    x: Int64;
    y: Int64;
}

struct Player {
    position: Point;
    target: Point?;
    inventory: Array;
}

let player = Player {
    position: Point { x: 3, y: 5 },
    target: null,
    inventory: ["钥匙", "药水"]
};

player.position.x = 4;
player.target = Point { x: 8, y: 2 };
```

字段类型使用已确认的 `Int64`、`Float64`、`Bool`、`String`、`Array` 或已声明的结构名称。普通 `T` 字段不可空，`T?` 显式允许 `null`；可空仍要求构造时填写该字段。类型约束在实例创建及字段写入时检查，不扩展到普通变量、参数或返回值。

实例构造写作 `类型名 { 字段名: 值, 字段名: 值 }`，字段之间用逗号分隔，所有字段各填写一次；点号用于字段访问。声明中的分号与构造中的逗号具有不同用途。

#### 3.48.4 条件分支与循环

`if`、`while` 和 `for` 的头部必须有圆括号；分支和循环体必须有花括号。`else if` 使用两个关键字，写法如下；代码中的 `...` 仅表示省略的语句，不是 MYB 语法：

```text
if (condition) {
    ...
} else if (other_condition) {
    ...
} else {
    ...
}

while (condition) {
    ...
}

for (let item in source) {
    ...
}
```

`if`/`while` 条件须为 Bool。`for (let item in source)` 遍历数组或字符串，为循环变量建立局部绑定；一次求值、字符串按码点遍历、数组修改限制等仍按 D53–D55 执行。`break;` 结束最内层循环，`continue;` 进入最内层循环的下一轮。

#### 3.48.5 数据访问、逻辑符号与除法

数组字面量写作 `[value1, value2]`，允许空数组、混合类型和嵌套数组。数组与字符串索引写作 `value[index]`，普通切片写作 `value[start:end]`，支持省略端点和负端点；结构字段访问写作 `value.field`。相关语义仍按已有决定，不新增切片步长或字符串原地修改。

逻辑符号确定为 `&&`、`||`、`!`，分别表示与、或、非。实际求值的操作数及结果均为 Bool；`&&` 左侧为 false、`||` 左侧为 true 时跳过右侧。示例使用圆括号明确组合关系：

```text
(divisor != 0) && (total / divisor > 10)
(state == "ready") || (state == "paused")
!game_over
```

普通 `/` 返回浮点结果；整数除法使用 `//`，向下取整；余数使用 `%`，非零结果与除数同号：

```text
5 / 2       # 2.5
-5 // 2     # -3
-5 % 2      # 1
```

此处仅展示表达式的值；程序中可以写成 `let quotient = -5 // 2;` 等带分号的语句。完整优先级及结合性见 D64；`//` 与 `%` 严格要求两个 Int64 操作数。

#### 3.48.6 单行注释

| 写法 | 解码后的内容 |
|---|---|
| `\n` | 换行 |
| `\r` | 回车 |
| `\t` | 制表符 |

#### 3.49.4 字面量范围与数值边界

- 整数字面量必须符合 Int64 范围，超出范围报错，不自动转为 Float64。

- 极小浮点字面量允许下溢，包括舍入为 `0.0`。例如 `1e-9999` 可为 0.0，`1e9999` 则因溢出报错。D63 此条针对字面量；运行时浮点算术允许下溢已按 D64 确认，字符串转数值接口已按 D65 确认，十进制浮点解析的精确舍入另见 D72。

### 3.50 表达式、求值顺序与语法边界

2026-10-17，用户整体采用第二组推荐方案（D64）。本节补齐表达式组合、赋值与调用的执行顺序、数值运算边界；既有类型检查、短路、共享、作用域与声明初始化规则继续有效。

#### 3.50.1 优先级与结合性

从高到低采用以下七层。圆括号 `(expression)` 可改变分组；优先级规定组合关系，不替代实际求值顺序：

| 层级 | 运算 | 组合方式 |
|---|---|---|
| 1，最高 | 函数调用、字段访问、索引与切片：`f(...)`、`.field`、`[...]` | 从左向右连接 |
| 2 | 一元 `+`、`-`、`!` | 从右向左组合 |
| 3 | `*`、`/`、`//`、`%` | 左结合 |
| 4 | `+`、`-` | 左结合 |
| 5 | `<`、`<=`、`>`、`>=`、`==`、`!=` | 同一层，不连续链写 |
| 6 | `&&` | 左结合，短路 |
| 7，最低 | `\|\|` | 左结合，短路 |

例如 `1 + 2 * 3` 为 7，`(1 + 2) * 3` 为 9，`10 - 3 - 2` 按 `(10 - 3) - 2` 计算得到 5。一元 `+`、`-` 只接受数值，`!` 只接受 Bool。

`a < b < c`、`a == b == c` 等连续比较为语法错误；范围判断写作 `(low <= x) && (x < high)`。如果要对比较结果继续比较，须用圆括号显式分组。调用形式仍受 D61 的命名函数/内置接口约束，不因此引入函数值。

#### 3.50.2 赋值与表达式语句

赋值是语句，不作为表达式。合法赋值目标为已有变量、数组元素或结构字段：

```text
score = 90;
board[0] = 1;
player.position.x = 3;
```

首版不提供 `a = b = 1;` 形式的链式赋值、不提供切片赋值，也不允许在条件中使用赋值。字符串仍不可原地修改；结构字段仍按声明类型及可空约束检查。

普通表达式可以独立加分号执行，结果被丢弃；函数调用同样可以独立成语句。表达式语句不会隐式变成函数返回值，正常走到函数末尾仍返回 null。

#### 3.50.3 赋值执行顺序

执行普通赋值时，先完整计算右侧，随后确定左侧位置，最后检查并写入：

1. 求右侧表达式得到要存入的值。
2. 查找左侧变量，或计算左侧的数组对象、下标、字段接收对象等；每个表达式只求值一次。
3. 校验目标的可写性、有效下标或字段约束，通过后写入。

例如 `board[index()] = value();` 先执行 value，再读取 board 并执行 index，最后检查下标并写入。右侧改变变量或数组时，后续左侧定位按照变化后的状态执行；左侧表达式内部继续按其自身规则求值，索引/切片定位采用 D69 的接收对象保留、检查及长度取值时机。

如果左侧检查失败，失败写入本身不替换目标，但右侧及左侧求值过程中已经发生的副作用保留，不提供事务回滚。

`let` 声明继续遵守 D50：先建立未初始化绑定，再计算初始值。本节的普通赋值顺序不撤销该规则。

#### 3.50.4 函数调用、数组与结构构造

执行函数调用时先检查目标可调用且实参数量匹配，再按源码从左到右计算实参，全部成功后进入函数体。对 `f(g(), h())`，仅在 f 的调用目标与数量检查通过后依次执行 g、h。目标不可调用、少传或多传时，不执行实参，也不进入函数体。

宿主内置函数同样先检查数量；实参全部求值成功后，再按对应接口要求检查实际值类型并执行操作。普通用户函数的形参仍不声明类型；函数体中的具体操作按实际值检查。

数组元素从左到右求值。结构构造先核对类型名称与字段集合，再按构造表达式中字段的源码书写顺序逐项求值并检查类型，与字段声明顺序无关；错误时停止后续求值，既有副作用保留。

普通二元运算先求左侧、再求右侧，随后检查并执行该运算；与/或按 D40 先检查左侧并在需要时才求右侧。任一步报错都停止当前求值，不回滚已发生的副作用。

#### 3.50.5 数值运算边界

- 普通数值运算沿用既有整数提升规则；Bool 不参与数值算术，字符串拼接仍只接受两个 String。
- `//`、`%` 首版严格要求两个操作数均为 Int64；浮点操作数报类型错误，不自动截断。`/` 仍返回浮点结果。
- 浮点算术允许正常舍入与下溢，包括得到零，与 D63 的字面量规则一致；除零、产生无穷大或 NaN 仍报错。
- 整数对每一步实际运算的结果检查溢出；不能因更大表达式的最终结果可能合法而忽略中间溢出。
- 最小 Int64 `// -1` 的整数商超范围，报错；最小 Int64 `% -1` 的结果为 0，正常返回，不能因内部借用的商计算超范围而拒绝该合法余数。

| 示例 | 结果 |
|---|---|
| `5.0 // 2` | 类型错误 |
| `5 % 2.0` | 类型错误 |
| `-9223372036854775808 // -1` | 整数溢出 |
| `-9223372036854775808 % -1` | Int64，0 |
| `1e-300 * 1e-300` | Float64，允许下溢为 0.0 |
| `1e308 * 1e308` | 浮点非有限结果错误 |
| `1.0 / 0.0` | 除零错误 |

上表展示表达式的预期结果，不是省略分号的程序语句。字符串转数值、非有限字符串拒绝及负零显示规则现已按 D65 确认，见第 3.51 节。

#### 3.50.6 其他语法边界

逗号分隔列表末尾不额外加逗号，包括数组元素、形参、实参和结构构造字段。首版不提供独立空语句 `;`；函数/结构定义、分支、循环及 D69 的独立代码块结束后不额外加分号，构造表达式所属简单语句仍须以分号结束。

首版不提供 `+=`、`++`、`--` 等额外运算符，使用时报错；计数更新写成 `i = i + 1;`。

#### 3.51.2 严格数值转换

- int 解析十进制整数，不接受小数点或指数；前导零仍为十进制。须保留 Int64 精度并检查范围。
- float 接受整数、小数和科学计数法文本，沿用 D63 的格式要求，额外允许开头符号及首尾空白。
- 不完整数字、尾部杂项、格式不支持或范围不合适均报转换错误，不只解析有效前缀。
- 浮点解析允许舍入和下溢，包括得到 0.0；拒绝无穷大、NaN 与溢出。

| 表达式 | 预期结果 |
|---|---|
| `int("007")` | Int64，7 |
| `int(" -12 ")` | Int64，-12 |
| `int(2.9)` | Int64，2 |
| `int("2.9")`、`int("1e3")` | 转换错误 |
| `int("9223372036854775808")` | 范围错误 |
| `float("12")` | Float64，12.0 |
| `float("-1.2e3")` | Float64，-1200.0 |
| `float("NaN")`、`float("inf")` | 转换错误 |
| `int(true)`、`float(null)` | 类型错误 |

本轮不因数值转换而引入隐式真值转换；额外的 Bool 专用转换接口未获确认。

#### 3.51.3 可恢复的文本解析

try_int/try_float 只接收 String，复用对应严格接口的文本解析规则。仅把文本内容无效、整数超范围或浮点溢出表示为 null；有效零返回数值 0 或 0.0，下溢归零仍属成功。参数类型不符合要求仍报类型错误，实参表达式中的错误也不由这两个函数吞掉。

```text
try_int("123");       # 123
try_int("0");         # 0，成功
try_int("abc");       # null，内容无效
try_float("2.5");     # 2.5
try_float("abc");     # null，内容无效
try_float("1e9999");  # null，溢出
```

读取输入与解析数字是两种独立能力。read_line 获得文本；int/float 表达“要求成功，否则报错”，try_int/try_float 让程序选择重试、跳过或提示，也能处理内存中已有的文本。函数名中的 try 只是普通名称的一部分，本条不引入 try/catch 语法或额外的 read_int 接口。

使用 read_line 的结果进行解析前，须先区分 EOF 返回的 null；不能把 null 直接传入只接受 String 的尝试解析函数。

#### 3.51.4 str 与复合值显示

- String 显示原内容；Bool 显示为 `true` 或 `false`，Null 显示为 `null`，Int64 使用十进制。
- Float64 使用简洁、能回读为原 Float64 值的表示；D72 细化为仅定点形式无小数部分时补 `.0`，科学形式不补；负零显示为 `-0.0`，精确格式见第 3.58 节。
- 数组和结构显示其内容；嵌套 String 带引号和必要转义。
- 遇到当前递归路径中的循环对象时，显示 `<cycle>`，避免无限展开。重复共享但不在当前路径中的对象不因此被当作循环。

str 返回 String；print/write 使用同样的显示结果执行输出。复合值格式化用于查看内容，不由此确认文件数据格式或序列化接口。浮点展示记法、完整标点、字段顺序及字符串转义已按 D72 明确，见第 3.58 节和核心规范第 9.1–9.3 节；该决定不选定宿主格式化算法。

#### 3.51.5 断言

assert 是固定两个参数的宿主内置函数：condition 必须为 Bool，message 必须为 String。条件为真时返回 null，不输出内容；条件为假产生断言错误，包含说明和源码位置。参数类型错误仍按类型错误处理，不将非 Bool 当作真假。

assert 沿用普通函数的实参求值规则：即使条件为真，message 表达式也会求值；没有惰性参数或短路函数机制。断言错误按 D68 向外传播并停止程序，使用已确认的诊断内容与 stderr；具体退出码和完整诊断文本格式仍待运行接口收口。

#### 3.51.6 完整输入处理示例与后续验证

### 3.53 四个基础文本处理接口

2026-10-17，用户对整套文本处理推荐规则回复“采用”（D67），确认下列四个接口统一作为首版宿主内置函数提供。它们与 D66 的文件接口组合完成读取、整理、解析与保存，不增加语法或流式文件资源机制；宿主语言仍待确定。

#### 3.53.1 签名与共同约束

| 接口 | 参数类型 | 结果与行为 |
|---|---|---|
| `split(text, separator)` | String、String；separator 非空 | 返回新数组，元素均为 String；从左到右按分隔符精确、不重叠地拆分，保留空片段 |
| `join(parts, separator)` | Array、String；parts 的每个元素须是 String | 返回用分隔符连接的字符串，空数组返回空字符串 |
| `trim(text)` | String | 返回裁去首尾 ASCII 空白的字符串，内部内容保持原样 |
| `split_lines(text)` | String | 返回由行内容组成的新数组，去掉匹配到的 CRLF/LF 行结束符 |

均使用固定数量的位置参数，遵守 D61 的内置名称保护和 D64 的调用检查与求值顺序。参数类型不符报错；join 不隐式调用 str，不将数字、null 或嵌套数组自动转换为文本。split 的空分隔符报错。

操作不修改原字符串或输入数组。返回字符串遵循 D11 的不可变规则；split/split_lines 返回独立的新数组，修改其元素或长度不改变源字符串。

#### 3.53.2 拆分、连接与首尾空白

split 的分隔符是普通字符串，可以包含多个码点；不解释正则、CSV 引号或转义。保留空片段使缺失字段的位置仍可识别：

```myb
split("张三,90,北京", ",");    # ["张三", "90", "北京"]
split("张三,,北京", ",");      # ["张三", "", "北京"]
split(",a,", ",");            # ["", "a", ""]
split("", ",");               # [""]
split("a--b--c", "--");       # ["a", "b", "c"]
split("aaa", "aa");           # ["", "a"]，从左到右不重叠

join(["张三", "90", "北京"], ",");    # "张三,90,北京"
join(["a", "b"], "");               # "ab"
join([], ",");                     # ""
join(["张三", str(90)], ",");       # "张三,90"
```

错误示例：`split("abc", "")` 的分隔符为空，`join(["张三", 90], ",")` 含非 String 元素，均报错；后者须由调用者显式转换，与 D02 一致。

trim 的 ASCII 空白准确为 U+0009–U+000D 和 U+0020，与 D65 数值字符串解析的首尾空白范围一致；不裁去全角空格，也不做 Unicode 规范化：

```myb
trim("  hello  ");         # "hello"
trim("\t你好\r\n");        # "你好"
trim("  hello world  ");   # "hello world"
trim("   ");              # ""
```

#### 3.53.3 拆行边界

CRLF 作为一个行结束符匹配，LF 也作为行结束符；单独 CR 是普通字符。内部空行保留，末尾单个行结束符不制造额外空行；空字符串返回空数组：

```myb
split_lines("a\r\nb\n");    # ["a", "b"]
split_lines("a\n\nb");      # ["a", "", "b"]
split_lines("a\n\n");       # ["a", ""]
split_lines("\n");          # [""]
split_lines("");            # []
split_lines("a\rb");        # ["a\rb"]，单独 CR 保留
```

#### 3.53.4 完整数据处理示例与验证重点

读取每行一个整数的文件，跳过空行，对非空但无法解析为 Int64 的行计数，保存合计与无效行数：

```myb
let lines = split_lines(read_text("numbers.txt"));
let total = 0;
let invalid = 0;

for (let line in lines) {
    let text = trim(line);

    if (text == "") {
        continue;
    }

    let value = try_int(text);

    if (value == null) {
        invalid = invalid + 1;
    } else {
        total = total + value;
    }
}

let report = join([
    "合计：" + str(total),
    "无效行：" + str(invalid)
], "\n") + "\n";

write_text("report.txt", report);
print("处理完成");
```

若输入为 `2\n\nabc\n3\n`，按规则推导保存的报告为 `合计：5\n无效行：1\n`，标准输出为“处理完成”并换行。示例总和仍按既定 Int64 溢出规则检查。

- 不可达分支与短路操作数不触发动态类型/名称错误；实际执行时区分未声明与未初始化。
- 非法 return/break/continue 的词法上下文及函数边界，重复声明检查与循环每轮作用域。
- 运行错误后停止后续语句、保留既有副作用、关闭宿主资源；类型/名称错误不绕过 D64 的赋值及调用求值顺序。
- stdout/stderr 分离、源位置与 MYB 调用栈、正常成功与错误失败。具体退出码和资源限额按后续正式契约实施。

### 3.55 索引、切片与独立代码块的补充规则

2026-10-18，用户回复“采用这两项补充”（D69），确认数据访问的检查/长度取值时机及独立代码块。本节限于语言语义与文法，不增加宿主接口、命令行约定或应用功能；尚未实现解释器。

#### 3.55.1 每次索引或切片的执行顺序

1. 计算接收对象并保留该值。
2. 计算实际写出的下标，或按起点、终点的顺序计算显式切片端点；每个表达式只求值一次，省略端点不执行表达式。
3. 上述求值全部成功后，检查接收对象支持对应访问，下标或显式端点符合类型要求。
4. 使用所保留对象此时的长度，按既有规则处理负下标、切片默认端点及范围，然后访问或生成切片。

若接收对象最终被发现不支持索引/切片，下标或端点表达式仍已执行；若任一表达式自身求值报错，则立即停止其后的表达式和本次访问，保留既有副作用（D68）。嵌套访问逐层应用本规则，内层访问失败便不再求值外层访问。

数组单个索引仍严格越界报错，不自动增长（D24）；普通切片仍按 D26 裁剪有效范围、按 D28 创建外层浅拷贝。端点函数中的增删仍须遵守 D54 的活动遍历限制，本轮不撤销该限制。

#### 3.55.2 端点副作用与接收对象

```myb
let values = [10, 20];

fn boundary() {
    append(values, 30);
    return 0;
}

let part = values[boundary():];
print(len(part));
```

按规则预期输出 3 并换行：先取得数组，再执行 boundary 使其长度变为 3，最后省略的终点按此时长度取 3。不能在端点求值前缓存旧长度 2 并据此决定访问范围。

如果端点函数把变量 values 改绑为另一个数组，当前访问仍使用最初取得的数组；对该原数组通过其他别名发生的合法修改，则会影响最终检查时看到的长度和元素。不在变量改绑后重新读取接收对象，也不为此隐式复制数组。

下标和显式切片端点必须为 Int64；Float64（包括 1.0）、Bool、String 和 null 不自动转换为整数。`values[:]` 是省略端点，`values[null:]` 是显式传入不合格端点而报类型错误，二者不同。整数范围和负端点/裁剪规则仍按原决定，不重新选择。

本节不改变 D64 的普通赋值顺序：`values[index()] = make_value();` 仍先完整执行右侧 make_value，再定位左侧并执行 index，之后检查并写入；调用目标/参数数量预检查及逻辑短路也保持原规则。

#### 3.55.3 独立花括号代码块

允许在普通语句位置使用独立的 `{ ... }`，包括文件顶层，用于限制临时名称的可见范围；沿用 D21/D46/D47 的块级词法作用域、最近绑定赋值与遮蔽规则：

```myb
let total = 0;

{
    let temporary = 3;
    total = total + temporary;
}

print(total);
```

按规则预期输出 3 并换行；temporary 在块外不可见，外层 total 的修改保留。结束的 `}` 后不额外加分号（D64）。块作用域的结束不使仍被其他绑定引用的对象失效，不引入隐式复制或新的对象生命周期规则。

独立块不是文件顶层声明位置的替代品；函数和结构仍只能直接在文件顶层声明（D45/D60），不能放入独立块后借此获得嵌套定义能力。非法声明位置及重复声明仍按 D68 执行前检查。

### 3.56 for 循环变量的精确声明作用域

2026-10-18，用户对 for 循环变量作用域整套推荐规则回复“采用”（D70）。该决定补齐 D55 的可见范围，不改变遍历、对象共享、普通 let 初始化及函数参数的既有规则，也当时不表示整份规范草案已经整体获批；后续整体确认见第 3.59 节。

#### 3.56.1 来源求值与每轮绑定

1. 在进入循环前的词法环境计算 source，尚未引入该循环的循环变量；同名读取仍指向此时可见的外层绑定。
2. 每轮取得当前元素后，建立循环变量局部绑定，与这一轮循环体最外层共用声明作用域。
3. 在该层再次 let 声明同名变量属于同作用域重复声明，按 D68 执行前检查；更内层的独立块或分支块可以遮蔽该普通变量。
4. 循环结束后，该循环变量不再可见，外层同名变量继续有效。

source 是取得遍历来源的表达式，不是普通 let 的初始值表达式：先取得来源，再将各轮元素绑定给循环变量。因此本规则不撤销 D50 的普通声明先建立未初始化绑定再求初始值，也不改变 D51 的函数参数与函数体最外层共用声明作用域。更深块的同名 let 初始化仍遵守 D50；外层绑定继续有效不代表恢复它进入循环前的值，source 或循环体已有副作用仍保留。

#### 3.56.2 同名来源与循环变量示例

```myb
let values = [10, 20];

for (let values in values) {
    print(values);
}

print(len(values));
```

按规则预期依次输出 10、20、2，各占一行。in 后的 values 读取外层数组，循环体内的 values 是当前元素，循环结束后读取的又是外层数组。仅循环变量自身的改绑不写回数组槽位，不改变外层变量绑定。

以下程序包含同层重复声明，执行前报错，不执行 source 或任何用户语句：

```myb
let values = [10, 20];

for (let item in values) {
    let item = 99;
}
```

需要临时遮蔽时可以使用更内层的独立块：

```myb
let values = [10];

for (let item in values) {
    {
        let item = 99;
        print(item);
    }
    print(item);
}
```

按规则预期依次输出 99、10，各占一行；内部绑定结束后，当前轮循环变量继续可见。

#### 3.56.3 不变的遍历语义与验证重点

source 仍只求值一次并保留遍历对象；来源变量改绑不切换遍历对象，不隐式创建快照。每轮绑定当前元素，元素是可变对象时仍共享；允许替换未访问的槽位并在后续读取最新值，禁止通过任何别名增删活动遍历数组（D54/D55）。

以上示例均为阅读推导，尚无解释器执行证据。后续验证包括同名来源先解析外层、来源求值次数、循环体同层重名执行前拒绝、内层遮蔽与恢复、循环结束后外层绑定有效、循环变量改绑不写回槽位，以及 D54/D55 的活动遍历及对象共享规则继续有效。

#### 3.57.1 空代码块、空函数体与零字段结构

#### 3.57.2 圆括号包裹赋值目标

去掉赋值目标最外层的分组括号后，仍须满足 D64 的目标形状：普通变量、最终索引或最终字段访问；实际可写性及字段/下标检查沿用原规则。括号不会复制对象、改变绑定、提前读取目标或改变先完整右侧再定位左侧的执行顺序。

```myb
let x;
(x) = 1;

let values = [10, 20];
(values[0]) = 99;

print(x);
print(values[0]);
```

按规则预期输出 1、99，各占一行；(x) 作为赋值目标不会先读取未初始化的 x。计算接收对象仍合法，例如 `(make_array()[0]) = value;` 的最终目标是数组元素；不能因接收对象来自调用而额外禁止。

`(1 + 2) = 3;` 是非法目标；`(values[:]) = [];` 仍是禁止的最终切片赋值。中间的切片/调用结果作为后续索引或字段的接收对象不因本节被禁止。

#### 3.57.3 最小 Int64 的直接负号例外

十进制整数字面量幅值 9223372036854775808 只有在一元负号直接作用于该整数 token 时，才能形成合法 Int64 最小值。正常词法分隔空白或注释可以处于负号与数字之间，数字 token 本身不能拆开；前导零仍按 D63 的十进制规则解释。

“直接”按既有优先级判断：负号的操作数本身必须是整数 token，不能隔着分组括号或附着的访问后缀。允许给已经完整写出的合法负值加分组括号，不允许先把越界正幅值作为独立值，再依靠外层运算修复它。

| 写法 | 结果 |
|---|---|
| `-9223372036854775808` | 合法 Int64 最小值 |
| `- 9223372036854775808` | 合法 |
| `(-9223372036854775808)` | 合法，括号包住完整负值 |
| `9223372036854775808` | 执行前报字面量越界 |
| `-(9223372036854775808)` | 执行前报错，括号内正幅值非法 |
| `+(-9223372036854775808)` | 对合法最小值执行一元加，正常返回该值 |
| `-(-9223372036854775808)` | 实际执行外层取负时发生整数溢出 |

合法最小值形成后的外围运算继续按 D09/D64 检查，不把运行时溢出改成非法字面量；非法正幅值则按 D63/D68 在执行前拒绝。具体前端处理方式仍留到解释器设计，本条不引入任意精度整数或扩大 Int64 值域。

|---|---|
| `1.0` / `1e3` | `1.0` / `1000.0` |

| `1e-4` / `1e-5` | `0.0001` / `1e-5` |
| 正零 / 负零 | `0.0` / `-0.0` |

### 4.3 文件读写与标准库

用户询问过能否通过 MYB 的库实现文件读写。已经解释的可行分工是：

1. 解释器通过宿主语言（候选为 C++）提供实际访问操作系统文件的底层函数。
2. MYB 编写的上层库可以调用这些函数，实现按行处理、配置解析、应用数据保存等功能。
3. 单独增加文件操作函数不要求同时实现多文件导入系统。

首版已按 D66 确认方案 A：宿主提供 `read_text(path)` 与 `write_text(path, text)`，采用 UTF-8 整文件读取与创建/覆盖写入，具体编码、换行、路径及失败规则见第 3.52 节。未来方案 B 可新增流式文件接口并保留 A 的既有接口和含义；文件对象、追加及流式资源规则未纳入首版。

split/join/trim/split_lines 四个文本辅助函数已在文件路线之后另行按 D67 确认，详见第 3.53 节。不因此自动确认其他文本库或文件接口。

随机数、多文件导入也仍待定。用户希望同时覆盖数据处理工具与实时命令行游戏，具体交付应用尚未选定，可由这些应用需求帮助判断能力优先级。

### 4.4 应用目标：数据处理与实时命令行游戏

用户明确希望 MYB 可用于数据处理工具，也能编写像样的命令行俄罗斯方块、贪吃蛇。该目标不等于已经要求首版交付这两款游戏，也未确定数据处理规模或性能指标。

助手建议以“面向数据处理与终端交互应用的小型通用解释语言”为设计取向，分为通用语言核心、宿主提供的底层能力、可用 MYB 编写的上层库与应用逻辑。以下是从应用目标推导的候选需求，尚未逐项批准：

| 使用场景 | 要检验的语言能力 | 候选库与运行时能力 |
|---|---|---|
| 数据处理工具 | 字符串处理、数组与结构、遍历、函数、数值计算 | 文本文件读写、拆分与转换、排序；CSV 等格式解析按实际需要选择 |
| 贪吃蛇 | 坐标结构、可增长数组、状态更新、循环与函数 | 无需回车的按键输入、非阻塞或有界等待的按键读取、计时、随机数、终端局部刷新 |
| 俄罗斯方块 | 棋盘数组、方块结构、旋转与碰撞检测、状态组织 | 同类终端输入输出与计时能力，组合绘制一帧后输出以减少闪烁 |

游戏循环可采用单线程的“读取可用输入 → 根据时间更新状态 → 绘制 → 短暂等待”，不因此要求首版引入线程、异步语法、类或继承。普通等待输入一整行的接口不能独自满足自动移动和下落的交互目标。实际流畅度仍需在实现后测量，不能先承诺 AST 解释器的帧率。

文件访问、终端输入模式、光标控制、计时等底层操作需要宿主或平台接口支持；MYB 上层库可以封装这些接口。终端模式与光标状态应在正常退出和运行时错误退出时恢复。Unicode 码点长度不等于终端显示列宽，首版棋盘可优先用 ASCII 格子，避免将字符串索引规则直接当作绘制宽度规则。

首版运行平台已确认，见第 4.5 节。应用片段仅用于检验语言表达能力；按用户最新要求，当前先完成核心规范，终端接口与详细分层方案留到其后单独讨论，仍是设计建议。

### 4.5 平台范围：Windows 首版，保留 Linux 扩展能力

用户已确认首版先支持 Windows，保留支持 Linux 的能力。首版不要求交付或验证 Linux 后端，也不能宣称已经兼容 Linux。

为落实这个约束，助手建议语言核心与平台操作分离：词法语法、值类型、作用域和应用逻辑不直接依赖 Windows；按键输入、终端绘制与模式恢复等通过统一的内部接口交由平台适配层处理。可移植的文件与计时实现可以复用，不必为每个函数都创建两套后端。

面向 MYB 程序的接口应表达“方向键”“绘制位置”“经过的时间”等含义，避免要求应用使用 Windows 专用键码或系统句柄。未来增加 Linux 适配时，目标是保留同一套语言语义与应用接口；仍需补充平台实现和实际测试，不能保证仅重新编译即可运行。具体 API、宿主依赖和支持的 Windows 终端环境尚待架构阶段确定。

可增长数组、混合类型元素、单个索引、普通切片浅拷贝、数组赋值/传参共享对象、宿主内置函数显式深拷贝及命名结构固定字段名已确认，见 D22–D38 和第 3.16–3.24 节。结构字段已改为显式声明类型并在运行时检查（修订后的 D33），普通变量仍动态改绑。结构实例赋值与传参共享（D34）、数值字段转换（D35）已确认；按名称构造（D36）、构造时全部字段各填一次且无默认值（D37）已确认；数组及命名结构字段规则已确认（D38）；显式可空字段已确认（D42）；结构顶层预登记与递归字段类型已确认（D60）；函数递归已确认（D45），deep_copy 保留共享与循环关系已确认（D59）。

## 5. 实现路线的讨论状态

现有实施步骤以 **C++17 + Flex + Bison + AST 执行器** 为规划基线，目的是衔接用户学习过的编译原理工具。它仍是候选路线，并未因语言语义的确认而自动定稿。

已解释的职责划分：Flex 生成 Lexer，Bison 生成 Parser；自定义语义动作构造 AST；变量环境、运行时值、控制流、函数、数组/结构和 I/O 由解释器实现。

此前的 Go + 手写前端是更早的建议，不应再被当成已经确定的技术选型。使用哪种宿主语言和前端工具，不决定 MYB 必须采用静态类型还是动态类型。

## 6. 当前讨论位置：以数据处理和终端游戏检验设计

字符串编码、长度与索引单位、不可变性、负下标及采用切片语法已确认，见 D10–D13 和第 3.6、3.7 节，不必重复询问。此前只支持非负下标的决定已被用户明确替代。代码块已选择花括号，简单语句已选择分号结束，见 D14、D15 和第 3.8、3.9 节。

变量必须显式声明、允许重新绑定不同类型均已确认，见 D16、修订后的 D17 和第 3.10–3.12 节。旧 D18 已废止。浮点数显式转整数向零截断、截断结果超出 Int64 范围报错（D19），允许延迟初始化且初始化前读取报错（D20），也均已确认；无需再次询问。

用户此前关注：采用负下标和切片后，看起来很像 Python，目前哪些部分与 Python 不同？2026-10-12 已进一步改为整数除法向下取整，因此整数商与余数不再是与 Python 的差异。已确认差异包括整数范围、数值异常策略、代码块、简单语句结束方式和变量声明；不能把尚未选定的语法或内部实现技术算作既定语言特色。

| 方面 | MYB 已确认规则 | Python 3 |
|---|---|---|
| 整数范围 | 固定 Int64，溢出报错 | 任意精度整数，受可用资源限制 |
| 浮点非有限运算结果 | 运算产生无穷大或 NaN 时报错 | 可以表示无穷大和 NaN；部分运算产生它们，部分异常运算仍报错 |
| 代码块边界 | 花括号 `{ ... }` | 缩进 |
| 简单语句结束 | 必须写分号 | 通常由逻辑行结束，允许分号 |
| 变量创建 | 必须显式声明 | 普通名称赋值可以建立绑定，不要求独立的变量声明 |
| 条件/循环块内的局部变量 | 在块内声明的变量不在块外可见 | 普通 `if`/`for`/`while` 不创建新的局部变量作用域 |

Python 数值规则参考：[官方文档](https://docs.python.org/3/library/stdtypes.html#numeric-types-int-float-complex)。本地 Python 3.13.5 验证了上述整数示例，以及两个值为 `1e308` 的浮点变量相乘得到 `inf`。MYB 的对应行为目前是设计约束，尚未实现。

动态类型及重新绑定、数字与字符串显式转换、混合算术提升、浮点除法、整数除法向下取整及其配套余数、不可变字符串、按码点索引、负下标与切片，与 Python 相同或相近。变量重新绑定不再列为与 Python 的差异。UTF-8 内部存储属于实现决定，不能单独当作语法特色。

原始需求允许吸收不同语言的优点，但要求体现自身特色且不能与现存语言完全相同。代码块已确定使用花括号，变量须显式声明；声明关键字、函数和结构等整体语法已按 D62 确认，切片边界见 D25–D28；源码与字面量已按 D63 确认，表达式规则已按 D64 确认，EBNF 已写入核心规范 v0.2，已获整体确认。

用户曾担心 MYB 混合不同语言规则却缺乏统一取向。比较静态类型、动态类型和运行时固定变量类型后，用户明确选择：“那就改成动态类型，允许重新绑定不同类型吧”。此前提出的静态类型加有限推断方案未被采用，不能作为当前实施方向。
